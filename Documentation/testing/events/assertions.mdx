Every `Append` and `AppendMany` call returns an `IAppendResult`. The `Cratis.Chronicle.Testing` package provides built-in `Should*` extension methods for asserting on these results.

## Assertion reference

| Method | Asserts |
|--------|---------|
| `result.ShouldBeSuccessful()` | `IsSuccess` is `true` |
| `result.ShouldBeFailed()` | `IsSuccess` is `false` |
| `result.ShouldHaveConstraintViolations()` | `HasConstraintViolations` is `true` |
| `result.ShouldNotHaveConstraintViolations()` | `HasConstraintViolations` is `false` |
| `result.ShouldHaveConstraintViolationFor(name)` | A violation for the named constraint is present |
| `result.ShouldHaveConstraintViolation(name)` | Singular alias for `ShouldHaveConstraintViolationFor(name)` |
| `result.ShouldHaveConcurrencyViolations()` | `HasConcurrencyViolations` is `true` |
| `result.ShouldNotHaveConcurrencyViolations()` | `HasConcurrencyViolations` is `false` |
| `result.ShouldHaveErrors()` | `HasErrors` is `true` |
| `result.ShouldNotHaveErrors()` | `HasErrors` is `false` |

The success, violation, and error assertions check result flags, not collection counts. The named-constraint methods search `ConstraintViolations` for the supplied name.

All `Should*` methods throw `AppendResultAssertionException` on failure. Diagnostics depend on the method:

- `ShouldBeSuccessful()` lists constraint violations and errors when their flags are set, and notes concurrency violations when flagged.
- `ShouldNotHaveConstraintViolations()` lists constraint violations; `ShouldNotHaveErrors()` lists errors.
- The named-constraint methods list actual constraint violations when `HasConstraintViolations` is set.
- The remaining methods report the expected and actual flag state without listing individual violations or errors.
