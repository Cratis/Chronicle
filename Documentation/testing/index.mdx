# Testing

Chronicle provides lightweight, in-process test utilities that let you verify event appending behavior, read model projections, and reactor side-effects without a running server or database. Tests are fast, isolated, and require no infrastructure.

:::note[Client coverage]
`Cratis.Chronicle.Testing` and its in-process `*Scenario` helpers (`EventScenario`, `ReadModelScenario<T>`, `ReactorScenario<T>`) are a C#-specific test library layered on xUnit and Cratis.Specifications. Kotlin, Elixir, and TypeScript each have their own general-purpose test tooling (Kotest/JUnit, ExUnit, Vitest/Mocha) but no Chronicle-specific in-process test utility package — testing a Chronicle-backed slice in those clients means exercising the real client SDK directly against a running event store, not an in-process scenario helper. All of `testing/**` in this section is therefore C#-only.
:::

In Cratis applications, Chronicle tests usually sit inside [Cratis Specifications](/testing-with-cratis/). That makes the event-sourced shape explicit: `Establish()` or a scenario's `Given` builder seeds facts that already happened, `Because()` appends or provides the event under test, and each `[Fact]` asserts the new facts, read model state, or side effect.
