<a id="event-append-collection"></a>

Cratis Chronicle's `IEventAppendCollection` captures event-log append outcomes from the client under test, so you can assert on both the events your operation produces and their results. Use it with the .NET integration fixtures when a test needs a running kernel. It does not observe appends made by another client or process, even against the same event store.

## How It Works

Call `StartCollectingAppends()` on the fixture before the operation you want to test. The collector subscribes to the event log's `AppendOperations` notifications and keeps each event and its append result together as an `AppendedEventWithResult`. Direct calls to `EventStore.EventLog.Append` and `EventStore.EventLog.AppendMany` use this path. So do reactors that call `ICommandPipeline.Execute()`, because the command pipeline commits its unit of work through `AppendMany` on the same client.

The collection includes rejected appends as well as successful ones. An idempotent retry that returns an already-appended result does not emit a new append notification, so it does not add another entry.

For a direct `Append`, the entry is available when the awaited call returns. A reactor's follow-up append can arrive later: use `WaitForCount()` before asserting on that event. Waiting for a count confirms that append outcomes arrived; it does not by itself confirm other observer work.

## One-Time Test Project Setup

Add the `Cratis.Chronicle.XUnit.Integration` package for `IEventAppendCollection` and `ChronicleInProcessFixture`. The in-process fixture runs the kernel in the test process and MongoDB through Testcontainers, so this setup needs a container runtime.

Define an xUnit collection to share the fixture among test classes marked with that collection. The project-local `Specification` base below binds `Specification<TChronicleFixture>` to `ChronicleInProcessFixture`, so each context can use the same base. ## Scope Lifetime

Start collecting in `Because()`, immediately before the operation under test. That keeps setup events out of the assertions. Store the collector on the `given` context so the facts can inspect it, then dispose it in `Destroy()`:

<ChronicleClientTabs snippet="testing/event-append-collection/scope-lifetime" />

Disposal unsubscribes the collector, so later appends no longer accumulate in it. While a scope is active, it captures notifications from the subscribed event log, not only events for one event source. Filter by event type or context when other activity on that client could be present.

## AppendedEventWithResult Members

Each entry in `All` pairs the event passed to the append with the operation's outcome. Check `Result` before treating the event as successfully stored:

| Member | Type | Description |
|---|---|---|
| `Event` | `AppendedEvent` | The event submitted for append, including its context and content |
| `Event.Content` | `object` | The event object supplied to the append (cast to your event type for assertions) |
| `Event.Context` | `EventContext` | Metadata: event source, sequence number, correlation ID, causation chain, etc. |
| `Event.Context.EventSourceId` | `EventSourceId` | The event source the event was appended for |
| `Event.Context.SequenceNumber` | `EventSequenceNumber` | Assigned position, or unavailable for a failed append |
| `Event.Context.CorrelationId` | `CorrelationId` | The append's correlation ID |
| `Event.Context.Causation` | `IEnumerable<Causation>` | The causation chain active at the time of the append |
| `Result` | `AppendResult` | The outcome of the append operation |
| `Result.IsSuccess` | `bool` | `true` when there are no constraint violations, concurrency violations, or errors |
| `Result.SequenceNumber` | `EventSequenceNumber` | Assigned sequence number; `EventSequenceNumber.Unavailable` when the append failed |
| `Result.HasConstraintViolations` | `bool` | `true` when at least one constraint violation was returned |
| `Result.HasConcurrencyViolations` | `bool` | `true` when at least one concurrency violation was returned |
| `Result.HasErrors` | `bool` | `true` when at least one error was returned |
| `Result.ConstraintViolations` | `IEnumerable<ConstraintViolation>` | Constraint violations, if any |
| `Result.ConcurrencyViolation` | `ConcurrencyViolation?` | Concurrency violation, if any |
| `Result.Errors` | `IEnumerable<AppendError>` | Errors, if any |

## Asserting on Collected Events

`IEventAppendCollection` exposes three members:

| Member | Description |
|---|---|
| `All` | A snapshot of every `AppendedEventWithResult` captured so far |
| `Last` | The most recently captured `AppendedEventWithResult`; throws when nothing has been collected |
| `WaitForCount(count, timeout?)` | Waits asynchronously until at least `count` events have been collected |
