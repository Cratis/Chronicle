---
title: Close a stream of a definition
description: Close one stream of an event source so the kernel refuses further appends to it, with a closing event or with a call, using the names from the definition.
---

Use this page to end one stream of a definition, such as one month of an account, and keep the rest of the event source open. The mechanism, its guarantees and its limits are the general ones in [Closing streams](../closing-streams/index.mdx). This page shows how to aim it at a definition's streams.

A closure is a scope made of up to four values: event source id, event source type, event stream type and event stream id. A definition supplies the names for three of them. The closure refuses an append when every value the closure sets equals the append's value. Closing the `Transactions` stream with id `2026-04` of account `A` refuses only that account's April transactions.

## Close with an event

When a domain fact ends the stream, declare it with `[ClosesStream]` on the event type. The kernel writes the event and the closure together. By default the closed scope is the appended event's event source id, stream type and stream id, so append the closing event through the definition, to the stream it ends:

The closing event is accepted. Every later append to the same account's `2026-04` stream is refused with a `StreamClosed` constraint violation. Other months and other accounts are unaffected. The declaration options, such as `ReopenedBy` and `EventStreamIdFrom`, are in [Closing events](../closing-streams/closing-events.mdx).

Add `expectedTailSequenceNumber` to close only if nothing was appended since the last fact you know of, as described in [Scoped closing](../closing-streams/scoped-closing.mdx#close-only-if-nothing-landed).

## Things to know

- There is no typed `CompleteStream<TSource>`. You build the scope from the definition's values.
- Closing a stream does not touch the definition. A closure is stored by value, so renaming a stream later leaves the old closure on the old name. See [Questions and pitfalls](./faq.mdx#what-happens-when-i-rename-an-event-source-or-a-stream).
- A scope that is only the default stream, with no event source id, is refused with `DefaultStreamCannotBeCompleted`. Appends without a stream go to the default stream, so close the whole event source by id if you want those closed.
