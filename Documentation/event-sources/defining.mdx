---
title: Define Cratis Chronicle event sources and streams
description: Declare a Cratis Chronicle event source in C#, choose stable stream names and concurrency dimensions, and inspect the registered definition.
---

Define an event source in Cratis Chronicle to keep its routing names and default concurrency settings consistent across writers. In the .NET client, an `IEventSource` class carries that declaration; callers still supply the id of the account, cart or other instance they write to. Once it is registered, you can [append through the definition](./appending.mdx).

## Declare the definition

Create a class that implements `IEventSource`. Use `[EventSource]` for its name, description and default concurrency dimensions, and add one `[EventStream]` for each named part of its history. Leave the class body empty:

<ChronicleClientTabs snippet="event-sources/defining/definition" variants="csharp" />

| Attribute | Property | Meaning |
|---|---|---|
| `[EventSource]` | name (constructor) | The event source type written on every event appended through the definition |
| | `Description` | Shown in the Workbench |
| | `Concurrency` | The default [concurrency dimensions](./concurrency.mdx) for every stream |
| `[EventStream]` | name (constructor) | The event stream type written on events appended to the stream |
| | `Description` | Shown in the Workbench |
| | `Concurrency` | The dimensions for this stream. When none, the event source's dimensions apply |

Chronicle reads the attributes during artifact discovery and registers the resulting definition when the event store connects. It never creates an instance of the class, so there is no entity state or constructor to maintain here.

## Choose the names

The event source name becomes the stored event source type, and each stream name becomes a stored stream type. Observers match those values, so keep them stable when you rename code.

<ChronicleClientTabs snippet="event-sources/defining/naming" variants="csharp" />

- An explicit name in `[EventSource("Loan")]` wins.
- Without one, the name is the type name with a trailing `EventSource` removed. A type that is itself called `EventSource` keeps its name.
- The attribute is optional. Without it the definition has no description and declares no concurrency dimensions.
- Names are compared exactly. `Account` and `account` are different event source types.

Two definitions with the same name make discovery throw `DuplicateEventSourceName`. A definition that declares the same stream twice throws `DuplicateEventStreamName`.

## Choose the concurrency dimensions

`ConcurrencyDimensions` is a flags enum: combine its values with `|` to choose the fields that narrow a default concurrency check. An omitted field does not restrict the check. Include `EventSourceId` when the boundary belongs to one entity; leaving it out makes the condition apply across source ids.

| Flag | The guard covers events with the same |
|---|---|
| `EventSourceId` | event source id |
| `EventSourceType` | event source type |
| `EventStreamType` | event stream type |
| `EventStreamId` | event stream id |
| `None` | Nothing is declared. The append keeps the guard it would have had without a definition |

A stream's declared dimensions replace the event source's dimensions; they are not added to them. `None` on a stream means it inherits the source's settings, not that it disables checking. Use [Concurrency](./concurrency.mdx) to work out which writers each combination makes conflict.

## Choose the stream ids

A stream declares a type only. The stream id is a value you pass on each append, and Chronicle does not impose a format or a template for it. Keep the convention in one place so every writer produces the same string:

<ChronicleClientTabs snippet="event-sources/defining/stream-id-convention" variants="csharp" />

For a stream that exists once per account, such as `Onboarding`, omit `eventStreamId` to use the default stream id. There is no month or other instance value to distinguish in that case.

## Where Chronicle finds definitions

The client discovers every non-abstract, non-generic class that implements `IEventSource` in the application's assemblies, together with its other artifacts. With [explicit artifact registration](../clients/dotnet/explicit-artifacts.md) you nominate definitions in the composition root instead. Registration with the kernel happens when the event store connects. [How it works](./how-it-works.mdx#discovery-and-registration) has the sequence.

## Check what is registered

Read the definition back from the client:

<ChronicleClientTabs snippet="event-sources/defining/inspect" variants="csharp" />

After discovery, `IEventStore.EventSources` lets you look up the definition by type or name. Check that its name, streams and dimensions match what your writers expect. In the Workbench, open the event store's **Event Sources** page to inspect the kernel's registered definitions. It shows the name, description, owner and default concurrency, with stream names and their own dimensions in the detail pane. See [Workbench](../workbench/index.mdx).
