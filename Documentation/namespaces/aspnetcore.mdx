---
title: "Cratis Chronicle ASP.NET Core namespace resolution"
description: "Configure Cratis Chronicle namespace resolution in ASP.NET Core to route requests to tenant data, with authorization handled by your application."
---

The Cratis Chronicle ASP.NET Core client selects a namespace from the current request when the scoped event store is first resolved. Use a header, subdomain, or custom resolver to route tenant operations to that namespace. Your application must authorize the caller for the selected tenant; choosing a namespace does not grant access to it.

If you already use Cratis Arc tenancy, use its tenant-to-namespace mapping rather than introducing a second tenant selection rule. See [Arc tenancy](/arc/backend/csharp/tenancy/).

## Built-in resolvers

### HTTP header resolution (default)

The default resolver reads `x-cratis-tenant-id`. Configure the header name through `ChronicleAspNetCoreOptions`:

<ChronicleClientTabs snippet="namespaces/aspnetcore/http-header-resolver" />

When the header is present, its value becomes the namespace. If the header or HTTP context is missing, the resolver returns the default namespace.

:::caution[The caller chooses the namespace]
The header resolver accepts the supplied value without checking tenant access. A caller who controls the header can select another tenant's namespace for the endpoint's operations. Use a trusted gateway that replaces caller-supplied tenant headers with an authorized tenant, or derive the namespace from the authenticated user. Reject requests without a tenant when access to the default namespace is not allowed.
:::

### Subdomain resolution

The subdomain resolver uses the first host segment when the host has more than two dot-separated segments: `tenant1.example.com` selects `tenant1`.

<ChronicleClientTabs snippet="namespaces/aspnetcore/subdomain-resolver" />

A host with two or fewer segments, or no HTTP context, selects the default namespace. The resolver parses the host; it does not check whether the caller belongs to that tenant. Validate the host and tenant access before using the event store.

## Configuration priority

1. Resolver set via `IChronicleBuilder.WithNamespaceResolver()` or `IChronicleBuilder.NamespaceResolver`
2. Type configuration (`EventStoreNamespaceResolverType`) when provided
3. Default HTTP header resolver
