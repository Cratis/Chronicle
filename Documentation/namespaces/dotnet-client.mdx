---
title: Cratis Chronicle .NET namespace resolution
description: Configure a namespace resolver for the Cratis Chronicle .NET client so direct clients and hosted services select the intended tenant's event store.
---
The Cratis Chronicle .NET client uses `IEventStoreNamespaceResolver` to select a namespace when you call `GetEventStore` without an explicit namespace. The returned event store stays bound to that namespace. Configure a resolver when a worker service or console application needs to select tenant data from its current execution context.

:::note[Client coverage]
The resolver APIs on this page are .NET-specific. For HTTP requests, use [ASP.NET Core namespace resolution](./aspnetcore), which covers request headers, subdomains, and web-host configuration.
:::

## IEventStoreNamespaceResolver

<ChronicleClientTabs snippet="namespaces/dotnet-client/resolver-shape" />

`Resolve()` returns an `EventStoreNamespaceName` for the current context. Passing a namespace explicitly to `GetEventStore` bypasses the resolver for that call.

## Built-in resolvers

### DefaultEventStoreNamespaceResolver

`DefaultEventStoreNamespaceResolver` always returns `EventStoreNamespaceName.Default`. Direct clients and non-web hosts use it when no resolver is supplied. Choose it when the application uses a single namespace.

### ClaimsBasedNamespaceResolver

`ClaimsBasedNamespaceResolver` reads a tenant claim from an authenticated principal. By default, it reads `ClaimsPrincipal.Current` and looks for `tenant_id`; the example shows how to choose a different claim type:

<ChronicleClientTabs snippet="namespaces/dotnet-client/claims-based" />

The resolver also accepts a principal-accessor callback when the principal comes from another context. If the principal is absent or unauthenticated, or the claim is missing or empty, it returns the default namespace. If your application requires a named tenant, reject that missing context before accessing the event store rather than treating the fallback as authorization.

## Configuring in a hosted application

For a worker service using `IHostApplicationBuilder`, either set `ChronicleClientOptions.EventStoreNamespaceResolverType` or supply an instance through `IChronicleBuilder`. The instance takes priority over the configured type:

<ChronicleClientTabs snippet="namespaces/dotnet-client/hosted-app-configuration" />

Chronicle creates type-based resolvers with dependency injection (DI) and keeps the resolver as a singleton. It resolves the namespace when the scoped `IEventStore` is first requested. Set the tenant context before resolving that service, and use a new scope for another tenant.

## Best practices

Keep tenant selection stable for the lifetime of an event store instance. Changing the resolver's context does not retarget an event store you already obtained; call `GetEventStore` again for the next tenant, or create a new DI scope in a hosted application.

Keep resolution quick and avoid blocking I/O in `Resolve()`. Decide explicitly whether a missing tenant may use the default namespace. Before relying on the setup, check that two tenant contexts select different namespaces and that missing context follows your chosen policy.

For request-based tenant selection and its authorization boundary, continue with [ASP.NET Core namespace resolution](aspnetcore).
