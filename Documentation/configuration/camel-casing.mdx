Configure camel case naming in the Chronicle .NET client when your stored event and read model properties need names such as `firstName` instead of `FirstName`. The same policy controls projection property mappings and read model container names.

## Overview

By default, the .NET client preserves C# property names. `CamelCaseNamingPolicy` converts those names to camelCase during serialization and projection definition building, so the definitions refer to the names written to storage. It also camel-cases read model container names; both the default policy and the camel case policy pluralize those names by default.

Choose the policy before the client initializes. This is a client dependency, not an ASP.NET Core JSON setting.

## Impact on Projections

The policy connects the C# properties in a projection to their serialized names. Your C# types keep their original property names.

### Projection Definition Building

When the client builds a projection definition, it applies the policy to property mappings. A mapping for `FirstName` therefore refers to `firstName` in the stored data.

## Important Notes

The policy applies to the projections built by that Chronicle client. It does not change general ASP.NET Core JSON serialization; configure that separately if your HTTP responses also need camelCase.

Changing the policy changes property paths and can change container names. Treat a change on an existing store as a storage-contract change, not just a display preference.

## Troubleshooting

### Projection Property Names Not Converting

Check the client that builds the projection. It must receive the policy before initialization, either through `WithCamelCaseNamingPolicy()` on its builder or through the constructor's `namingPolicy` argument. Configuring one client does not change another client instance.

### Inconsistent Property Naming

Compare the registered projection's property paths with the stored model, including any custom mappings. After changing the policy, rebuild the projection definitions with the configured client. See [Projections](../projections/index.md) for the projection workflow, or [Structural Dependencies](structural-dependencies) to configure a custom naming policy.
