---
title: "Chronicle .NET client structural dependencies"
description: "Supply custom Chronicle .NET client providers, resolvers, and naming policies through constructor arguments or the host registration callback."
---

Supply structural dependencies when the Chronicle .NET client needs your application's identity provider, namespace resolver, or artifact discovery. These dependencies are objects that define client behavior, so you pass them to `ChronicleClient` or set them during host registration rather than bind them from `appsettings.json`.

Keep connection strings, timeouts, and TLS settings in `ChronicleOptions`. For a hosted application, the separate `configure` callback receives an `IChronicleBuilder` before the dependency injection (DI) container is built. Use it to select the providers the client will use.

## Structural dependencies

| Dependency | Purpose | Default |
|---|---|---|
| `IClientArtifactsProvider` | Supplies event types, projections, reactors, and other client artifacts | `DefaultClientArtifactsProvider.Default`, using project- and package-referenced assemblies |
| `IIdentityProvider` | Supplies identity for event metadata | `BaseIdentityProvider`, returning the current identity or `Identity.System` when none is set |
| `ICorrelationIdAccessor` | Provides the current correlation ID for event metadata | `CorrelationIdAccessor`, returning the current async-local value or `Guid.Empty` |
| `IEventStoreNamespaceResolver` | Selects the event store namespace | `DefaultEventStoreNamespaceResolver`, returning the default namespace |
| `INamingPolicy` | Names serialized properties, projection mappings, and read model containers | `DefaultNamingPolicy`, preserving property names and pluralizing container names |
| `ILoggerFactory` | Creates loggers for the Chronicle client internals | A `LoggerFactory` without logging providers for direct construction; the host's factory for hosted registration |

The `myProvider` argument is an `IClientArtifactsProvider` supplied by your application; `artifactsProvider: myProvider` makes the client use it for artifact discovery. `LoggerFactory.Create(b => b.AddConsole())` sends the client's logs to the console. Omitted dependencies use the direct-construction defaults above.

## Configuring with IChronicleBuilder

For ASP.NET Core or a worker host, pass provider instances through the `configure` callback on `AddCratisChronicle`. It runs during registration, so it is not a place to resolve services from the finished DI container.

The same pattern works with `WebApplicationBuilder` in ASP.NET Core:

<ChronicleClientTabs snippet="configuration/structural-dependencies/aspnetcore-builder" />

Use `configureOptions` for bound settings: it runs after configuration binding and can override those values. Use `configure` for provider instances: configuration values cannot replace those objects.

When no custom provider is set on the builder, hosted registration can use a provider already registered in DI. For ASP.NET Core's defaults, see [Client Configuration](index.mdx) and the host setup it links to.

## IChronicleBuilder fluent methods

| Method | Sets |
|---|---|
| `WithArtifactsProvider(IClientArtifactsProvider)` | Custom artifact discovery |
| `WithIdentityProvider(IIdentityProvider)` | Custom identity resolution |
| `WithCorrelationIdAccessor(ICorrelationIdAccessor)` | Custom correlation ID accessor |
| `WithNamespaceResolver(IEventStoreNamespaceResolver)` | Custom namespace resolution |
| `WithCamelCaseNamingPolicy()` | Camel case property and container naming |

For another naming policy, assign `IChronicleBuilder.NamingPolicy` directly. Hosted clients use the host's `ILoggerFactory`; the builder has no logging-factory setter.

## DefaultClientArtifactsProvider

Keep `DefaultClientArtifactsProvider` when Chronicle's discovery rules fit and only the assembly set needs to change. It discovers artifacts on first property access. Supply a custom assembly provider to control which assemblies it searches:

<ChronicleClientTabs snippet="configuration/structural-dependencies/default-artifacts-provider" />

The static `DefaultClientArtifactsProvider.Default` instance uses project- and package-referenced assemblies. No explicit initialization call is required.

Continue to [Namespaces](../namespaces/index.md) to implement request-specific namespace selection, or [Camel Casing](camel-casing) to configure the naming policy.
