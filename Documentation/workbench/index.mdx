>
  Chronicle Workbench is the browser interface bundled with Chronicle's
  development images. Use it to inspect stored events, investigate observer
  failures, and view read models in your local instance. You can also preview
  the projection behavior supported by the running image.
</TopicHero>

Workbench inspects a running Chronicle instance. [Cratis Studio](/studio/) is a
separate, optional commercial workspace where teams collaboratively model
commands, events, read models, specifications, and screens. You do not need
Studio to use Workbench or build with Chronicle.

## Start locally

<Steps>
1. Pull and start the current development image with Chronicle available only
   on this machine. MongoDB remains internal to the container. Pin a released
   version in project-owned configuration when repeatability matters.

   ```bash
   docker run --pull=always --rm -d --name chronicle \
     -p 127.0.0.1:35000:35000 \
     cratis/chronicle:latest-development
   ```

1. Wait for the local health endpoint to report readiness. The development
   image uses a self-signed certificate, so this command disables certificate
   verification only for this local check.

   ```bash
   curl --insecure --fail --retry 30 --retry-all-errors --retry-delay 1 \
     https://localhost:35000/health
   ```

   Continue when the response prints `Healthy`.

1. Open `https://localhost:35000` in a browser and sign in. The
   [local access guide](development.md) explains the development certificate
   warning and built-in administrator account.

1. Select the event store and namespace you are authorized to inspect before
   opening their events or read-model instances.

1. Start with the observer or read model you are investigating. An observer
   processes events from an event sequence; its state and failed partitions
   help you find where processing stopped. A projection builds a read model
   from events, giving you a view of the resulting data.

1. Stop and remove the container when finished.

   ```bash
   docker rm -f chronicle
   ```

</Steps>

## What to inspect

Confirm the selected event store and namespace before interpreting read-model
instances: they belong to that selection. The connected-clients view instead
shows clients across the connected Chronicle cluster, regardless of the
selected event store or namespace. Workbench does not combine separate
Chronicle deployments.

When event processing fails, inspect the observer's state and its recorded
failed partitions. Each failed partition identifies an event source the
observer stopped processing and records its attempts. The read-only grouped
view organizes current failures by observer and failure kind so you can
see which failures belong together. To understand a particular attempt, open
its event as described below. For a projection change, use the preview behavior
supported by your running image rather than assuming every projection can be
previewed.

:::danger[Inspection does not authorize mutation]
Being able to inspect state does not grant permission to append, revise,
redact, replay, recover, control jobs, or otherwise change it. Keep the
development image and its default credentials out of staging and production
environments. For production, assess security and compatibility against your
deployment's requirements. This walkthrough covers local inspection, not full
administration, federation between instances, managed operations, or support
and SLA commitments.
:::

### Inspect an event from a failed attempt

In **Failed partitions**, select a partition and follow an attempt's sequence
number to inspect that exact event in the observer's event sequence. The
sequence number identifies the event's position within that sequence. The
inspector shows the selected store, namespace, sequence, and number alongside
the event details. This inspector does not offer compensation, revision, or
recovery actions.

Use **Return to failed partitions** to go back to the same scope and select the
originating failure if it still exists. If you select another partition or
clear the selection before the return selection finishes loading, your choice
takes precedence. Missing observers, events, or failures are reported rather
than replaced with a different event or partition. Event inspection accepts
only whole sequence numbers from 0 through 2147483647.

If you need to retry processing after investigating the event, follow
[Operating Chronicle](/chronicle/operations/) for recovery guidance.
