Chronicle uses a .NET/Orleans actor-based kernel behind gRPC/HTTP surfaces and
supports multiple event stores, namespaces, and persistent event-store
subscriptions with outbox/inbox sequences.

Use this page to start the self-hosted development profile and understand its
current kernel, store, namespace, subscription, and local inspection boundaries.

Chronicle and its bundled local Workbench are available as MIT-licensed
self-hosted software; authorized local use is separate from paid Cratis support,
hosted coordination, or managed operational responsibility.

## Current product boundary

- the kernel runs on .NET and Orleans behind gRPC/HTTP surfaces;
- event stores and namespaces are separate runtime scopes;
- persistent event-store subscriptions use outbox/inbox sequences; and
- the bundled local Workbench and separate CLI provide bounded inspection
  surfaces.

This page does not define client/provider parity, compatibility with every
product version, a supported topology, scale, durability, compliance, or managed
service.

## Start the reviewed development profile

The command below pins the reviewed Chronicle 16.38.2 development image by its
multi-platform OCI manifest digest. It starts Chronicle with the development
database profile on the local Chronicle and MongoDB ports.

```bash
docker run --rm -d --name chronicle \
  -p 27017:27017 -p 35000:35000 \
  cratis/chronicle@sha256:bc4d23570d29fdfb31a8f5ae689f6538e74ff2db7807e981438473d2283f4b07
```

Confirm the container is running:

```bash
docker ps --filter name=chronicle
```

Stop and remove it when the evaluation is complete:

```bash
docker rm -f chronicle
```

This startup result does not establish production suitability, support, scale,
security, durability, compatibility, or a managed service.

## Independent-use boundary

The self-hosted Chronicle kernel and bundled Workbench can be started without
Arc or Components. Applications and clients still require their own exact
package, protocol, version, configuration, and compatibility evidence.

## Inspection surfaces

Chronicle Workbench provides a bundled local browser surface for authorized
inspection of Chronicle runtime state and preview of supported projection
behavior.

The Cratis CLI provides terminal workflows for inspecting and diagnosing
Chronicle.

Inspection capability does not imply complete administration, production-ready
mutation, client parity, federation, managed service, support, or an SLA.
