<a id="tagging-reactors"></a>

Descriptive tags in Cratis Chronicle label a reactor by its purpose, domain or owner. Use them to identify related reactors in their definitions; they do not change which events a reactor handles.

In .NET, apply `[Tag]` or `[Tags]` to the reactor class. If your task is to restrict delivery instead, filter the appended event metadata by [tag](../events/filtering/by-tag), [event source type](../events/filtering/by-event-source-type), or [event stream type](../events/filtering/by-event-stream-type).

:::note[Client coverage]
Kotlin and Java tag a reactor with `@Tag`, which is repeatable and takes any number of tags. Elixir's `use Chronicle.Reactors.Reactor` and TypeScript's `reactor()` expose no way to attach descriptive tags to the reactor itself.
:::

## Best practices

Choose names a maintainer will recognize, such as a business domain or the team responsible for the reactor. Use the same spelling on related reactors so the labels remain useful when reading definitions. Add a tag only when it helps someone distinguish or find the reactor.

## Querying by tag

Reactor tags are stored with the reactor definition. Chronicle does not use them to activate or select reactors, so labeling a reactor `analytics` does not subscribe it to events tagged `analytics`.

To receive only events that carry a given tag, continue with [event-tag filtering](../events/filtering/by-tag.mdx). That configuration is separate from the descriptive attributes shown here.
