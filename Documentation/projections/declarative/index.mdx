Your profile projection started as a few attributes, but its keys, related data, or child collections now make the model hard to scan. A separate fluent definition lets the model remain the shape you query while the mapping has room of its own.

A declarative projection in Cratis Chronicle is a code-authored mapping definition executed by the kernel. It is still a projection, not an arbitrary event handler. Start with [model-bound attributes](../model-bound/index.mdx) when they are clear; use this chapter when a separate mapping is easier to read. [Choose how to build a read model](../choosing-a-read-model-style.mdx) compares that choice with reducer code.

## Overview

In the C# client, a projection class implements `IProjectionFor<TReadModel>` and describes its mappings in `Define(IProjectionBuilderFor<TReadModel>)`. The tabs show each client's declaration form.

Place the definition in the application's registered artifacts, with its read model and registered event types. This chapter assumes the application already connects to the intended Chronicle store and namespace. `Define` constructs the definition during registration; the kernel later applies it to events. Constructor dependencies may help build that definition, but the callbacks are not dependency-injected, per-event business logic.

## Discovery

A declaration can be correct without being registered in the running application. In .NET, default artifact discovery finds `IProjectionFor<TReadModel>` implementations and event types marked with `[EventType]`. With explicit artifact registration, nominate the required types; see [explicit artifacts](../../clients/dotnet/explicit-artifacts.md).

Each .NET projection class must target exactly one read model. Implementing two closed `IProjectionFor<TReadModel>` interfaces, including through inheritance, throws `TypeImplementsMultipleProjectionInterfaces` during default discovery. Split the class into one projection per model. [CHR0057](../../code-analysis/CHR0057) reports that shape before runtime.

After startup, inspect [registration outcomes](../../clients/dotnet/registration-outcome.md) if the expected definition is absent. A running client does not prove that every artifact registered.

## When to Use

Use the fluent builder for mapping structure: explicit keys, constants and context fields, joins, child collections, nested objects, or a model that should remain attribute-free. Counting and summing are built-in operations; they do not by themselves require a reducer.

Use a reducer when the update reads better as a state transition that branches on the previous state. Moving a projection to a fluent class does not make its mapping expressions arbitrary code. The [architecture](../architecture.mdx) explains where declaration ends and execution begins.

## Key concepts

### Auto-mapping vs explicit mapping

AutoMap copies compatible, same-name fields. Explicit mappings supply an event property path, constant, context value, or supported operation. In the C# builder, `NoAutoMap()` changes the scope's convention; it is not a per-event toggle. An explicit property mapping can coexist with AutoMap, and aggregate-only events have their own [AutoMap exception](auto-map.mdx#aggregate-only-events).

### Event handling

Declare each event type that should contribute. An event updates its mapped properties and leaves the others alone; Set replaces a property's value, while Add and Subtract accumulate. These declarations describe the kernel's work, not application callbacks to invoke after an append.

### Keys and identification

The event source ID is the default root key and parent identifier. Choose another key deliberately when grouping events. For children, define both the item's identity and how the event finds its parent; a child key is not a parent key. A join likewise needs a correlation property. Routing identifies the destination instance; it does not automatically populate a visible ID field.

### Container name

By default the read model is stored in a container (collection, table) named by the client's naming policy. In C#, call `ContainerName("name")` on the projection builder to choose a different one. This sets only the container name; the read model keeps its identifier, so the projection still resolves its read model. Every projection of the same read model must use the same container name, otherwise the client reports a conflict. Changing the container name of a read model that already has data points it at a new, empty container, so replay the projection afterwards.

:::caution[Code that names the collection by convention does not see the override]
Cratis Arc's MongoDB integration resolves `IMongoCollection<T>` and `IMongoDatabase.GetCollection<T>()` through the naming policy, so with an overridden container name they point at the default collection. Get the collection by the name you passed to `ContainerName`, for example `database.GetCollection<T>("name")`, or read the instance through Chronicle with `IReadModels.GetInstanceById<T>()`.
:::

### Checking the definition and the running system

Use a [read-model scenario](../../testing/read-models/scenario.mdx) to assert field values over a small event history, including the fields that should remain unchanged. Then check registration, catch-up, and queries against the intended kernel and sink. An in-process mapping test does not establish storage behavior, compliance, or asynchronous delivery. Changes to a deployed definition also need the [registration and evolution lifecycle](../registration-lifecycle.md), not just a passing mapping test.
