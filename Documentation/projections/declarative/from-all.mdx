<a id="projection-with-fromall"></a>

`FromAll` in Cratis Chronicle subscribes a projection to every event type in its event sequence, including types with no explicit `From` mapping. Use it in the .NET fluent API for results such as per-source event counts. Use [FromEvery](./from-every) when only the event types your projection already handles should contribute.

Events handled by the all-events subscription can create or update a read model instance for any event source. The default key is the event source ID. If you configure another all-events key, those events use that key instead.

## With event-specific mappings

Combine `FromAll` with `From` to map business fields for selected event types and metadata for every type. An event declared in `From` runs the all-events mappings through that registration once and uses its configured key.

Unrelated event types still contribute. They can create instances without the business fields set by the event-specific mappings. Choose `FromEvery` instead if that would leave read models your queries cannot use.

<ChronicleClientTabs snippet="projections/declarative/from-all/with-specific-mappings" />

## Join events

A declared `Join` event type is excluded from the separate all-events subscription so a matched event is not counted twice. Its all-events mappings run through the join instead.

If the join finds no read model instance, those mappings do not fall back to creating an instance under the event source ID. Keep this in mind when using `FromAll` to count events: a join-only event with no matching instance will not contribute a count.

## Child events

`FromAll` includes child-projection event types and has no child-exclusion switch. Child-only events apply its mappings once to their containing parent, using the child's resolved parent key. Unrelated event types use the configured all-events key. The root `all` block in the declaration language follows the same subscription scope.

For mappings limited to one projection level, use `FromEvery` with `ExcludeChildProjections()`, or `every` with `exclude children` in a declaration.

## Counting into a dictionary with a dynamic key

Use `Count`, `Increment`, or `Decrement` on a dictionary property when you need a separate counter for each context value. The key is resolved for each event from `EventContext`; this example uses the event type identifier. Dictionary keys are strings. The kernel stores counts using the dictionary's declared value type, or `int64` when the dictionary declares none. See [dictionary keys](./dictionaries) for every key source and for removing keys.

The model-bound `[FromAll]` attribute does not support this dictionary form. Use the fluent API shown above.

## FromAll and FromEvery

| API | Use it when |
| --- | --- |
| `FromAll` | Every event type in the sequence should contribute, including types not declared by the projection. |
| `FromEvery` | You want mappings applied to the projection's own handled event types, without subscribing to unrelated event types. |

Prefer [event context](./event-context) for shared metadata fields because it has a consistent shape across event types. Use payload properties only when the contributing event contracts intentionally share those properties.
