When auto-mapping isn't sufficient, you can explicitly map properties from events to your read model. This gives you full control over how data is transformed and mapped.

## Combining AutoMap with explicit mapping

AutoMap is on by default, so you never call `.AutoMap()` yourself: every property whose name matches is already mapped. Add explicit mappings only for the properties that need a transformation or a different source:

<ChronicleClientTabs snippet="projections/declarative/set-properties/combined-automap" />

AutoMap works recursively, automatically mapping:

- Properties with matching names and compatible types
- Nested objects and their properties
- Collections and arrays

`NoAutoMap()` turns it off for the projection (and `.AutoMap()` turns it back on inside a child scope) — there is no per-event-type toggle. Add explicit `.Set()` calls inside a specific `.From<TEvent>()` block for the properties that need custom mapping; AutoMap still fills in every other matching property for that event.

## Property mapping options

You can map properties in several ways:

- **From event property**: `.Set(m => m.CustomerName).To(e => e.Owner.Name)`
- **From constant value**: `.Set(m => m.IsActive).ToValue(true)`
- **From event context**: `.Set(m => m.OpenedAt).ToEventContextProperty(c => c.Occurred)`
- **From event source ID**: `.Set(m => m.Id).ToEventSourceId()`

> [!NOTE]
> `.To(...)` maps a single **event property** — it reads the value straight off the event, it does not run code. It cannot produce a *computed* value: `.To(e => $"{e.FirstName} {e.LastName}")`, `.To(_ => DateTimeOffset.UtcNow)` and similar expressions are not supported, because the builder extracts a property path from the expression rather than executing it. To derive a value, either record it on the event as a fact (compute it in the command's `Handle()` before appending) or use a [reducer](/chronicle/reducers/), which can run arbitrary logic over the current state and the event.

## Multiple events

A single projection can handle multiple event types, each with its own property mappings. Properties are updated incrementally as events are processed.

In the example above:

- `AccountOpened` sets initial values for all properties
- `MoneyDeposited` only updates `Balance` and `LastTransaction`
- Other properties retain their previous values

This approach gives you precise control over how your read models are built from events.
