`FromEventSequence()` in Cratis Chronicle selects the event sequence a projection reads. Use it when the events you need are stored outside the default `event-log` sequence. Event type mappings still decide which events contribute, but matching events in other sequences do not feed this projection.

## How it works

A projection reads from one selected sequence. Its observer tracks progress using sequence numbers from that sequence, and matching event types elsewhere are outside that subscription.

Sequence order is append order, not necessarily occurrence-time order. Sequence numbers identify positions within one sequence; they do not establish an order across several sequences. See [event sequences and observer offsets](../../concepts/event-sequence.md) for how reading resumes.

## When to use FromEventSequence

Choose the sequence used by the code that appends the events your query needs. For example, a shipping projection should read the shipping sequence if that is where shipment events are recorded.

Selecting a sequence does not configure tenant isolation or authorization, and it does not merge events from several sequences.

## Default behavior

For local event mappings without an explicit sequence selection, the projection uses `event-log`. Leave that default when your application appends the required events to the event log. Adding more `From` mappings does not make the projection read other sequences.

## Performance considerations

Sequence selection defines the input to the projection; it is not a performance guarantee. Consider the selected sequence's event volume and the work performed by the mappings when evaluating processing cost.

Once the source is selected, use [FromEvery](./from-every) for mappings shared by the event types the projection handles, or [FromAll](./from-all) when every event type in that sequence should contribute.
