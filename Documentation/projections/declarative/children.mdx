Child collections in Cratis Chronicle let you keep related items inside one read model, such as members inside a group. Configure both the parent key, which selects the group, and the child key, which selects the member to add, update, or remove.

## Defining a projection with children

Use `Children` to select the collection property, then `IdentifiedBy()` to select the property that identifies each stored child. Each event mapping supplies the child key with `UsingKey()`. The example maps group details at the root and membership changes inside `Members`.

## How children work

The root `From` mapping updates group details. The mappings inside `Children` update members instead. For each membership event, Chronicle first resolves the parent group, then matches the event's child key against the property selected by `IdentifiedBy()`.

A member with that key is updated if it exists, or added if it does not. Removal uses a separate `RemovedWith<>()` mapping.

## Parent key resolution

By default, Chronicle uses `EventSourceId`, the identifier attached when the event is appended, as the parent key. Leave that default when membership events are appended under the group's ID. Choose a parent key from event content when they are appended under another ID, such as the user's.

### When to use each approach

| Parent identifier location | Mapping |
| --- | --- |
| Event source ID | Leave the parent key unspecified. |
| Event content | Use `UsingParentKey(e => e.Property)`. |
| Event source ID, stated explicitly | Use `UsingParentKeyFromContext(ctx => ctx.EventSourceId)`. |

## Child lifecycle

A `From` mapping adds a child when its key is new and updates the child when the key already exists. This means an event named as an update can also create a missing child. Use `RemovedWith<>()` for removal rather than mapping a deletion event through `From`.

## Removing children

Configure the removal event with the same child-key strategy used by the add and update mappings:

<ChronicleClientTabs snippet="projections/declarative/children/removing" />

When the removal event arrives, Chronicle finds the member by `e.UserId` and removes it. If no member has that key, the collection stays unchanged. Add separate `RemovedWith<>()` mappings for other event types that remove members.
