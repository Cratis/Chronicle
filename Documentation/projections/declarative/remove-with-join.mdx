# Projection with RemoveWithJoin

`RemovedWithJoin<TEvent>()` in Cratis Chronicle removes matching child items across the parent read models maintained by a projection. Use it when a related entity changes independently: disbanding a group, for example, should remove that group's membership from every user's collection without listing the users in the event.

## Understanding RemoveWithJoin vs RemovedWith

`RemovedWith<TEvent>()` targets a child under a particular parent, using the event's parent and child keys. It fits a user leaving one group. The keys can come from event content; the event does not have to originate on the parent's event source.

`RemovedWithJoin<TEvent>()` uses a child key without requiring a parent key. It removes matching children across parents in this projection, which fits a group being disbanded for all its members.

## Basic RemoveWithJoin usage

Declare `RemovedWithJoin<>()` inside `Children(...)`, alongside the events that add and enrich the child:

<ChronicleClientTabs snippet="projections/declarative/remove-with-join/basic" />

The membership event routes to a user through `UsingParentKey(e => e.UserId)`. The child collection identifies each group through `IdentifiedBy(e => e.GroupId)`, while `Join` supplies the group's details. The deletion handler removes children matching its resolved key across users in this projection.

Keys default to the event source ID. The adding event's child key and the deletion event's removal key must resolve to the same group identifier. When that identifier is in event content instead, configure `UsingKey(...)` as in the explicit-key example below. Use `UsingParentKey(...)` when the parent identifier also comes from event content.

## How RemoveWithJoin works

When the projection processes the removal event, Chronicle resolves its key from the event source ID or the configured key expression. It then removes children whose `IdentifiedBy` value matches that key from the configured collection across parent instances.

This is a child-collection operation, not a search through every projection in the system. Root-level `RemovedWithJoin` removal is not supported.

## Best practices

### Use for cross-stream cleanup

Use `RemovedWithJoin<>()` when an event about one entity should remove its representation from many parent collections. This updates derived read models; it does not delete the source events or enforce a write-time relationship constraint.

### Combine with RemovedWith

Choose by the scope of the removal, not just by which stream emitted the event. Use `RemovedWith<>()` when you know the parent and child. Use `RemovedWithJoin<>()` when the child key should match across parents.

### Consider event ordering

Parent instances can be updated by different event-source partitions. Do not treat removal across their collections as a single atomic change. See [eventual consistency in projections](../eventual-consistency) when deciding what callers may read while processing catches up.

If you are still choosing the child identifier or routing membership events to a parent, start with [child projections](./children).
