<a id="constant-keys"></a>

A constant key in Cratis Chronicle directs events from different event sources into one read model instance. Use it when you need one order count or engagement total rather than a separate result for each source. Apply the same key to every event mapping that contributes to that result.

## Defining a constant key

Use `UsingConstantKey(string value)` on a `From` mapping to select a fixed read model key. The read model remains a normal record or class; you do not need a different model shape to share one instance across event sources.

<ChronicleClientTabs snippet="projections/declarative/constant-key/basic" />

Every handled order-placement event updates the same counter with the key `"global"`, regardless of its event source ID. A constant key changes where events are mapped; it does not subscribe the projection to additional event types or sequences.

## Comparison to other key strategies

| Strategy | Method | When to use |
|---|---|---|
| Event source ID | (default) | Keep one instance per event source ID. |
| Event property | `UsingKey(e => e.Property)` | Identify the instance from event content. |
| Event context | `UsingKeyFromContext(c => c.Property)` | Identify the instance from event metadata. |
| Composite | `UsingCompositeKey<T>(...)` | Use several values together as the identity. |
| Constant | `UsingConstantKey("value")` | Direct the configured events to one shared instance. |
