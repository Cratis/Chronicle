Event context in Cratis Chronicle is metadata stored alongside an event rather than in its business payload. Map it into a read model when a query needs to show when an update occurred, identify its source, or connect it to a related operation without adding those fields to every event contract.

## Available event context properties

Common `EventContext` properties used in projection mappings include:

- `EventSourceId` - The identifier of the event source that produced the event
- `SequenceNumber` - The position of the event in the event sequence
- `Occurred` - When the event occurred (timestamp)
- `EventType` - Information about the event type
- `EventSourceType` - The type of the event source
- `EventStreamType` - The type of the event stream
- `EventStreamId` - The identifier of the event stream
- `CorrelationId` - The correlation identifier linking related operations
- `Causation` - The recorded chain of causes that led to the event
- `CausedBy` - Identity information about who caused the event

## Common use cases

### Audit trails

Map `Occurred`, `SequenceNumber`, and `CausedBy` when the query needs timing, sequence position, and the recorded identity behind an update. Choose which events and business values the audit view must retain; metadata alone is not a complete audit trail.

### Debugging and diagnostics

Store `CorrelationId` when you need to look up related events or operations carrying that identifier.

### Time-based queries

Use `Occurred` to group or filter results by occurrence time. For weekly keys, pair the ISO week number with its week-year as shown in [composite keys](./composite-keys#iso-week-keys).

### Event ordering

Store `SequenceNumber` to retain an event's position within its event sequence. Copying it into a property does not sort a child collection or establish order across different sequences.

### Source tracking

Use `EventSourceId` to identify the event source associated with an update.

For metadata that should update across the event types your projection already handles, continue with [FromEvery](./from-every). Use [FromAll](./from-all) only when unrelated event types in the sequence should contribute too.
