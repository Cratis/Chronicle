AutoMap in Cratis Chronicle maps event properties to read model properties with matching names. It is enabled by default in declarative projections, so you can declare the events a read model needs without repeating each property assignment.

Use explicit mappings where names differ or a value comes from somewhere other than the event payload. Keep event and read model property types compatible; AutoMap is a naming convention, not a value transformation.

## Basic usage

Declare each event with `From`. In this example, the creation event supplies `Name` and `Email`; the rename event changes only `Name`.

## How AutoMap works

For events that supply read model values, AutoMap uses these rules:

| Rule | Behavior |
| --- | --- |
| Property names | Chronicle compares serialized schema property names without regard to case. The client's naming policy determines those serialized names. |
| Property types | Choose event values compatible with the target property type. |
| Explicit mappings | An explicit mapping takes precedence over AutoMap for the same target property in that event mapping. |
| Scope | Child scopes inherit the parent's setting unless they override it. |

The kernel resolves matching properties when it constructs the projection's mappings from the schemas, rather than discovering them through reflection for each event.

## AutoMap with joins

AutoMap also applies to joined events. The join condition finds the read model to update; AutoMap supplies matching values such as `DepartmentName`.

## Aggregate-only events

When an event's mappings consist only of `Count`, `Increment`, `Decrement`, `Add`, or `Subtract`, AutoMap does not copy its other properties. In this example, counting submitted candidates leaves the arrangement's `Location` unchanged, even though the candidate event also has a `Location` property. You do not need to disable AutoMap for this behavior.

<ChronicleClientTabs snippet="projections/declarative/auto-map/aggregate-only" />

## When to use AutoMap

Use AutoMap for properties that should retain the event's name and value. Add explicit mappings for renamed properties, constants, event context, and calculations. If you need every assignment to be visible in the projection definition, disable AutoMap and map each property yourself.
