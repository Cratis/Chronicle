# Projection With FromEvery

Use `FromEvery` in a Cratis Chronicle projection to update shared fields, such as a last-updated timestamp, whenever the projection handles an event. It saves you from repeating the same mapping in each event declaration. It does not subscribe the projection to unrelated event types; use [FromAll](from-all) for that.

The client APIs use different names: .NET has `FromEvery`, TypeScript has `fromEvery`, and Elixir has `from_every`. The examples show the declaration for each client.

## Constant Values

In .NET, `FromEvery` and `FromAll` both support `.Set(m => m.Status).ToValue("active")` to assign a constant whenever a matching event is processed. Concept values are unwrapped. Enums with an `int` underlying type use their numeric value; other enums use their name. Use `.ToValue<string?>(null)` to clear a nullable property.

Pass a value of the read model property's own type. `ToValue` infers its type from the supplied value, not the target property, so an incompatible value can compile without being reported when the projection is defined.

## Child Projection Inclusion

In .NET, `FromEvery` includes events handled only by child projections by default, including events in nested child collections. Those events update the containing parent's every-event fields using the child's resolved parent key. They do not create a separate root keyed by the child identifier. A parent's last-updated timestamp can therefore reflect changes to its children as well as its own events.

Call `ExcludeChildProjections()` when the field should track only the level where you declared it. That level's own `from` and `join` events still apply the mappings. In the declaration language, `every` also includes child events by default; add `exclude children` to opt out.

<ChronicleClientTabs snippet="projections/declarative/from-every/exclude-children" />

Keep `FromEvery` when a parent's audit fields should follow only events the projection already handles. A root `FromAll` mapping also subscribes to unrelated event types in the sequence and includes child events by default; choose it only when you need that wider subscription.

## Common Use Cases

| Use case | Typical source |
| --- | --- |
| Audit timestamp | Event context occurrence time |
| Event sequencing | Event context sequence number |
| Correlation tracking | Event context correlation id |
| Event source identification | Event source id |

If only selected events should update a property, put its mapping in those events' [Set properties](set-properties) declarations instead. For a value that should exist before any mapping assigns it, use [Initial values](initial-values).
