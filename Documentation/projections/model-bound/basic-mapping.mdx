Use model-bound mapping in Cratis Chronicle when a read model property needs a value from an event or its metadata. Declare the mapping on the read model: you can replace a value, add or subtract an amount, or record when a particular event occurred.

Client syntax differs. The examples below show each client's way to declare the event type, the key that selects a read model instance, and the property mappings.

## Set A Property From An Event

A set mapping replaces the current read model value with a property from the event. Use an explicit source name when the event and read model name the value differently.

## Set A Property From Event Context

Event context is metadata stored alongside the event payload. It includes occurrence time, event source identity, sequence information, and correlation metadata. Use a context mapping when the read model needs one of these values rather than a field from the payload.

### Derived Context Values

To group events by week, derive the week number from their occurrence time. `Occurred.Week` and `Occurred.Week()` both select the ISO week number. Pair it with `Occurred.WeekYear`, the ISO week-numbering year, which can differ from the calendar year near New Year.

These paths work on properties and record parameters with `[SetFromContext<T>]`, and with `[FromEvery(contextProperty: ...)]`.

<ChronicleClientTabs snippet="projections/model-bound/basic-mapping/derived-context" />

In .NET, the function must be the final path segment, take no arguments, and support the type of the value it reads. `Week` and `WeekYear` support `DateTimeOffset`, `DateTime`, and `DateOnly`, including nullable values. Unknown functions and incompatible value types are rejected when building the projection.

An actual .NET property takes precedence over a bare function name. Naming policies apply to property segments, not function names: under camel casing, `Occurred.Week` becomes `$eventContext(occurred.Week())`.

## Set A Value Only Once

Set `SetOnce = true` on `SetFrom` or `SetFromContext` when a property should keep the first value it gets. The mapping assigns the value only while the property has no value - it is missing or null - and later events leave it unchanged. ## Choosing The Mapping

| Mapping | Use it when |
| --- | --- |
| Set | A read model property should take a value from a specific event. |
| Set once | A property should keep the first value an event supplies, such as who created something or when. |
| Add | A numeric property should increase when an event occurs. |
| Subtract | A numeric property should decrease when an event occurs. |
| Context | A read model property should come from event metadata. |
| Every event | A property should update for any event that affects the projection. |

For changes of exactly one, use [counters](counters); for a value that should become `null`, use [clearing](clearing). If the mapping needs branching, state-dependent logic, or calculations that are clearer as code, use a [reducer](../../reducers/) instead.
