# Event Sequence Source

A model-bound projection reads events from one event sequence. In .NET, Chronicle uses the event log unless the model selects another sequence or its event types imply an inbox. Set `[EventSequence]` on the read model when you need to choose the source explicitly:

<ChronicleClientTabs snippet="projections/model-bound/event-sequence-source/model-bound" />

The model-bound attribute selects `custom-sequence` for the read model. A separate fluent projection makes the same choice with `FromEventSequence`:

<ChronicleClientTabs snippet="projections/model-bound/event-sequence-source/fluent" />

The examples use .NET attributes. For TypeScript model-bound models, use `@eventSequence('custom-sequence')`; the event-sequence argument on `@projection` applies to fluent projections. Elixir takes `event_sequence:` on `use Chronicle.ReadModels.ReadModel`; Kotlin and Java accept `eventSequence` on `@Projection`.

## Automatic Inbox Routing

Without an explicit sequence, the .NET client checks the event types in the projection's `From` mappings. If their `[EventStore]` metadata names a different event store, Chronicle selects that store's inbox sequence. You do not need an `[EventSequence]` annotation for this routing.

If the metadata names the current event store, or no store is specified, Chronicle selects the event log. The client rejects a model whose source event types name more than one event store.

## When to use `[EventSequence]` explicitly

- When you need to read from a specific sequence other than the inferred one
- To suppress automatic inbox routing for a projection that handles foreign events
- For projections that target a specialized or partitioned event stream

The old `[FromEventSequence]` attribute has been removed. Use `[EventSequence]` instead. Once the source is selected, use [From Every Event](./from-every.mdx) for mappings across handled events or [From All](./from-all.mdx) to subscribe to every event type in that sequence.
