# Constant Keys

Use a constant key in Cratis Chronicle when events from different event sources should update one shared read model instance. Instead of selecting an instance by the event source id, the mapping uses a fixed string, such as `"metrics"`. This lets a counter track a total across sources rather than a separate total for each source.

## FromEvent with ConstantKey

Every matching order-placement event updates the same summary instance, regardless of its event source. A constant key selects the destination; the property's mappings still decide whether to replace a value, add an amount, or count the event.

## Mixing event source key and constant key

A read model can use the event source id for one event type and a constant key for another. The destination is selected per event mapping, not once for the entire read model type:

<ChronicleClientTabs snippet="projections/model-bound/constant-key/mixed-keys" />

The registration event selects a user-specific dashboard. The order counter selects the document with key `"global-stats"`; it does not copy the platform total into every user's dashboard. Both documents use the same read model type, but they are different instances.
