---
title: "FromEvery: update audit fields from handled events"
description: "FromEvery updates a Chronicle read model property for each handled event, so audit fields can track occurrence time, sequence number, or correlation id."
---
`FromEvery` updates a read model property whenever the projection processes a handled event. Use it to maintain a last-modified timestamp or identify the operation that last changed the model without repeating the mapping for each event type.

An event-specific mapping runs only for its declared event type. An every-event mapping runs across the projection's handled types; it does not subscribe to unrelated types in the sequence. Use [From All](./from-all.mdx) when you need that wider subscription.

## Use Cases

| Use case | Typical source |
| --- | --- |
| Last modification time | Event context occurrence time |
| Last event sequence | Event context sequence number |
| Last operation id | Event context correlation id |
| Current status shared by all events | Event payload property |

Prefer context properties for audit metadata. Use payload properties only when the event contracts are intentionally consistent. If a property should update only for selected event types, use an event-specific mapping instead.

## Child Events

In .NET, a root `[FromEvery]` includes events handled only by child projections, including nested child collections. Chronicle uses the child's resolved parent key to update the containing parent's audit fields. It does not create a root document keyed by the child identifier.

A child-only event advances a root `[FromEvery]` timestamp even without a root `[FromEvent]` for that event. In the declaration language, `every` includes child events by default; use `exclude children` to keep mappings local to their level.

Put `[FromEvery]` on a child's own property when the child needs its own audit value. That mapping applies on the creating event and later events handled by the child. The same ownership rule applies to nested objects and `[FromAll]`: the object declaring the property owns the mapping. Parent fields are never copied into a newly added child.

For compatibility with clients that still put child mappings at the root, see [Child and nested properties](./from-all.mdx#child-and-nested-properties). A property declared on both root and child cannot be disambiguated until the client is upgraded.

## Limitations

For child or nested every-mappings on join-only events, use the
[declarative alternative in model-bound limitations](./index.mdx#child-or-nested-every-mappings-on-join-only-events).

- Only one every-event mapping can target the same read model property.
- Payload-property mappings are skipped for events that do not carry the source property. A source property that is present with a null value still maps null.
- The .NET model-bound `[FromEvery]` attribute has no child-exclusion option today. Use a [declarative projection](../declarative/from-every) with `ExcludeChildProjections()` when you need that opt-out.
