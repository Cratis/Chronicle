<a id="removing-read-models"></a>

Use `RemovedWith` when an event means a read model or child item should no longer appear in a Cratis Chronicle model-bound projection. For a child shared across several parents, `RemovedWithJoin` removes the matching item from every parent that contains it. Root-level removal through a join is not supported.

## RemovedWithJoin

Do not use `RemovedWithJoin` to delete a root read model. The engine logs a warning and does not subscribe to that removal event; the .NET client also warns when it discovers the declaration. Use `RemovedWith` with a custom `key` if another event property identifies the root instance to delete.

### Class-Level Removal on Child Types

Apply `RemovedWith` directly to the child type when every parent using that type should inherit its removal rule:

<ChronicleClientTabs snippet="projections/model-bound/children/removal-class-level" />

Both examples remove the order line identified by `ItemId`. The property-level example takes the parent from the event source ID; the class-level example names it explicitly through `OrderId`.

### Parameters

For child removal, you can specify:

- `key`: the event property that identifies the child to remove.
- `parentKey`: the event property that identifies the parent; the default is `EventSourceId`.

## Best Practices

Check the event's identifiers before choosing a removal attribute. `RemovedWith` targets one root model or one parent's child; `RemovedWithJoin` targets a matching child across parents. An event coming from another source does not by itself require a join: a custom `key` can identify a root model directly.

For the collection identity and parent-key rules that removal depends on, continue with [Children](children.mdx).
