---
title: "Cratis Chronicle model-bound projections: Clear nullable values"
description: Use ClearWith in Cratis Chronicle model-bound projections to set a nullable read model member to null when an event removes its value.
---
Use `ClearWith` in a Cratis Chronicle model-bound projection when an event removes a value, such as deleting a note or dropping a due date. The member must be nullable: the mapping writes `null` when the event is processed, including when rebuilding the read model from earlier events.

## Basic Usage

Put `ClearWith` on the nullable member and name the event that clears it:

<ChronicleClientTabs snippet="projections/model-bound/clearing/basic" />

`MbClearingProjectNoted` populates `Note`; `MbClearingProjectNoteCleared` returns it to `null`. A later `MbClearingProjectNoted` can set it again. Clearing changes the value at that point in the stream; it does not prevent future updates.

## The Same Clear as a Null SetValue

`SetValue` with `null` builds the same mapping. Use `ClearWith` to name the clearing operation, or keep `SetValue(null)` alongside existing constant-value declarations:

## The Member Must Be Able to Hold No Value

A non-nullable member cannot represent a cleared value. [CHR0048](../../code-analysis/CHR0048) reports the declaration as a build warning, scheduled to become an error in the next major release. Building the projection also throws `CannotClearNonNullableMember`, so leaving the warning unaddressed fails at startup.

<ChronicleClientTabs snippet="projections/model-bound/clearing/nullable" />

Writing `""`, `0`, or `DateTimeOffset.MinValue` instead would record a specific value, not the absence of one. An empty string, for example, cannot tell a reader whether a note was cleared or was genuinely empty.

Choose the declaration that represents the fact you need:

| You mean | Declare |
| --- | --- |
| No value at all | A nullable member plus `[ClearWith<TEvent>]` |
| A specific value that happens to be the type default | `[SetValue<TEvent>("")]`, `[SetValue<TEvent>(0)]`, … |

## Nested Objects

Put `ClearWith` on a member inside a nested type to clear only that member. Put it on the nullable `Nested` member itself to clear the whole object. The nested type can also declare its own clearing event, as described in [Nested Objects](nested).

<ChronicleClientTabs snippet="projections/model-bound/clearing/nested-member" />

When several models share the nested type, declaring the clear on the owning member keeps that owner's event out of the shared type.

## When This Is the Wrong Fit

`ClearWith` sets a member to `null`; it is not a collection-removal operation. Use `RemovedWith` to remove a selected child or delete the root read model, as described in [Removal](removal). Applying `ClearWith` to a `ChildrenFrom` collection is not a supported way to remove every item.

If the member should fall back to a specific default rather than have no value, declare that value with `SetValue`.

## In the Projection Declaration Language

In the projection declaration language, use `clear` to name the member an event empties:

```text
projection Notes => MyApp.ReadModels.MbClearingProjectNotes
    from MbClearingProjectNoted
        note = note
    from MbClearingProjectNoteCleared
        clear note
```

Use the member path to clear a value inside a nested object. This is the declaration-language equivalent of the `MbClearingContract` attribute example above:

```text
projection Employees => MyApp.ReadModels.MbClearingEmployee
    from MbClearingNoticeWithdrawn
        clear contract.noticeGiven
```

`note = null` compiles to the same mapping, so existing declarations need no change. Prefer `clear` in new declarations to make the removal of a value explicit. Chronicle also writes `clear` when generating a declaration from a projection definition, regardless of the original spelling. See the [Projection Declaration Language](../projection-declaration-language/) for the rest of the syntax.

## In the Fluent API

In the .NET fluent API, use `Clear` at the root, inside `Children`, or inside `Nested`, wherever you would use `Set`:

<ChronicleClientTabs snippet="projections/model-bound/clearing/fluent" />

`Set(...).ToValue(null)` builds the same mapping and remains supported. Prefer `Clear` in new code so the operation reads like its model-bound counterpart, `ClearWith`.

The nullable rule still applies. C# generic constraints cannot reject a non-nullable reference member at this method's signature. Building the projection throws `CannotClearNonNullableMember` instead, and [CHR0048](../../code-analysis/CHR0048) reports both `Clear` and `ToValue(null)` at build time.

If you implement the builder interface yourself, implement `Clear` before using it. Its default interface implementation preserves compatibility for existing builders but throws `ClearNotSupported` when called.
