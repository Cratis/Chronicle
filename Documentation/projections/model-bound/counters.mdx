Use counters in Cratis Chronicle model-bound projections to track how many times an event happened or how many items are currently active. `Increment` and `Count` add one to a numeric property; `Decrement` subtracts one. Choose the operation and property names to make clear whether the value represents a current quantity or an event total.

## Increment

Apply `Increment` to a numeric property when each matching event should increase its current value by one. It does not read an amount from the event payload.

<ChronicleClientTabs snippet="projections/model-bound/counters/basic-increment" />

Each login event adds one to `LoginCount` on the selected read model instance.

## Decrement

Pair `Decrement` with `Increment` when a quantity can rise and fall, such as the number of active connections.

<ChronicleClientTabs snippet="projections/model-bound/counters/increment-decrement" />

A connection event adds one to `ActiveConnections`; a disconnection event subtracts one. Both operations change the current value rather than keeping separate totals.

## Count

Use `Count` to express that a property records occurrences of an event. If the property has no value yet, counting starts at zero, then adds one for each matching event.

`Count` uses the property's current value, just as `Increment` does. It does not maintain a separate tally. If another mapping sets or changes that property, subsequent counts continue from the changed value.

## Counter vs Count

`Count` and `Increment` both add one to the stored property. Their distinction is intent: `Count` reads as an event total, while `Increment` paired with `Decrement` reads as a changing quantity. Neither protects the value from other mappings.

To retain a total alongside a current quantity, declare separate properties, as in the examples above. Use [`AddFrom` or `SubtractFrom`](basic-mapping#add-and-subtract-values) when the event carries an amount instead of representing a change of one.

## Best Practices

Check which read model instance receives the counter event. By default, its event source id selects the instance, so events from different sources do not automatically contribute to one global total. Use a [constant key](constant-key) when they should.

If a creation event supplies an initial quantity, set it with `SetFrom` before later events adjust it. Keep an event-total property dedicated to counting when it must not be reset by that initialization.
