description: Use convention-based mapping in Cratis Chronicle to copy matching event properties to read models, with explicit mappings for exceptions.
---
Use convention-based mapping in Cratis Chronicle when an event and a read model share property names and compatible shapes. Declare the source event on the read model, and Chronicle copies the matching properties without a set mapping on each one. This is the model-bound form of `AutoMap`.

Add explicit mappings for exceptions: a different source name, a value from event context, or an operation such as adding an amount instead of replacing a value.

## How It Works

Chronicle matches event properties to read model properties by name and compatible type. Nested objects can map when their internal names match; collections can map when their element shapes are compatible. A read model property absent from the event is left unchanged for that event.

Client syntax differs, but each client produces a projection definition containing the event type, the key that selects a read model instance, and the automatic mapping behavior.

By default, convention-based mappings use the event source id as the read model key. Use a custom key when the event carries the identifier of the read model instance in its content.

## Excluding A Property From Mapping

An event subscribed through a property mapping or join can also carry properties that match by convention. An explicit mapping from one event does not, by itself, stop another event from overwriting the same read model property by name.

Events used only for aggregation are excluded automatically. For other collisions, exclude the affected property with `[NoAutoMap]`.

### Aggregate-Only Events

When every mapping for an event is an aggregate operation, such as count, increment, decrement, add, or subtract, Chronicle does not copy that event's other properties by convention. Counting an event therefore cannot, on its own, overwrite a name or description with an unrelated same-named field. No exclusion attribute is needed.

<ChronicleClientTabs snippet="projections/model-bound/convention-based/aggregate-only" />

### `[NoAutoMap]` On A Property

For a collision involving a value-mapped (`[SetFrom]`) or joined (`[Join]`) event, apply `[NoAutoMap]` to the read model property or record parameter. Only explicit mappings can then change that property; the other properties keep mapping by convention.

<ChronicleClientTabs snippet="projections/model-bound/convention-based/no-auto-map-property" />

`[NoAutoMap]` also works at the read model (class) level to disable convention mapping for the whole read model. Use the property form when you only need to protect a single property and want convention mapping everywhere else.

## When To Use It

Start with convention mapping when most properties are direct copies and names are consistent. Add explicit mappings where the source or operation differs, and use a property-level exclusion when a value must only come from its declared source.

The client builds the projection definition from the model metadata; Chronicle processes events using that definition rather than reflecting over your model attributes for every event. For the explicit operations, continue with [basic property mapping](basic-mapping).
