---
title: Cratis Chronicle projection tags
description: Label Chronicle projection definitions with tags in C# or TypeScript to describe their purpose or domain, without filtering the events they observe.
---
Projection tags in Cratis Chronicle label a projection definition with its purpose or domain, such as `Analytics` or `Inventory`. Use them to describe what a projection is for. They do not filter the events it observes or select projections for operations such as rebuilds.

To control projection input, declare the event types and select the event sequence. If you need a reducer or reactor to process only events with particular metadata, use [appended event metadata filters](../events/filtering/index.md) instead of projection tags.

:::note[Client coverage]
C# supports `[Tag]` and `[Tags]`; TypeScript supports `@tag` and `@tags`. Apply them to the projection class, or to the read model for a model-bound projection. Kotlin and Elixir do not support projection tags. The kernel stores and returns tags with the projection definition. Changing only tags does not trigger a replay or replay recommendation.
:::

## Best Practices

Choose names a teammate can recognize without opening the projection's mappings. Reuse the same spelling for the same domain or purpose across projections, and add a tag only when it helps describe the projection. This gives related definitions a shared vocabulary without implying that Chronicle groups them for execution.

## Querying by Tag

Projection tags are stored metadata, not a query or rebuild selector. Adding `Analytics` to several projections does not make Chronicle select or rebuild them as a group. To change which events build a read model, edit the projection's event declarations or event sequence selection.
