# Ad-hoc Querying with `IProjections.Query()`

Use `IProjections.Query()` in the Cratis Chronicle .NET client to inspect projected state without registering a permanent projection. Send a Projection Declaration Language (PDL) declaration and receive read model entries as JSON strings. You can omit the read model type when exploring a small set of events.

> [!WARNING]
> Each call reads from the beginning of the selected event sequence, up to 1,000 matching events.
> If more events match, the results are incomplete. Use this API for small, bounded investigations,
> not as a replacement for a registered projection. Repeated calls repeat the event processing work.

## Basic Usage

Start with a connected .NET client and registered event types for the events named in your declaration. Inject `IProjections` into your service, then call `Query()` with the PDL string:

<ChronicleClientTabs snippet="projections/projection-declaration-language/adhoc-querying/basic" />

`ReadModelEntries` is an `IReadOnlyList<string>`. Each string represents one projected read model instance. The example deserializes those strings into `PdlOrderSummary` records for the caller; that local result type does not need to be registered as a read model.

## Explicit vs. Inferred Read Model

Include `=> ReadModelType` when you want to use an existing registered read model schema. The target must be its registered identifier, such as `MyApp.ReadModels.PdlOrderReadModel`, rather than a display name. Omit the target to let the server infer a schema from the event properties.

<ChronicleClientTabs snippet="projections/projection-declaration-language/adhoc-querying/inferred-vs-explicit" />

In the inferred declaration, both `from` blocks contribute properties to the same schema. If those events share a property name, its types must be compatible. A string in one event and an integer in another produces a compiler error at query time:

<ChronicleClientTabs snippet="projections/projection-declaration-language/adhoc-querying/type-mismatch" />

## Practical Use Cases

Use an ad-hoc query when you need a one-off view of a known, small event set: inspecting an order during diagnosis, exploring event data while developing a feature, or asserting projected state in a test. Check the number of matching events before relying on the result. A successful call does not establish that the query processed the full history.

## Limitations

| Concern | Detail |
|---------|--------|
| Event volume | The server reads at most 1,000 matching events. More matching events mean incomplete results. |
| No persistence | Results are not stored. Every call processes events again from the beginning of the selected sequence. |
| No registration | `Query()` does not register a projection, with or without an explicit `=> ReadModelType` target. |
| No change notifications | Results are a point-in-time snapshot; this API has no observable or reactive variant. |

For a view that stays up to date as events arrive, define a [registered projection](../declarative/simple-projection.mdx). For declaration syntax and Chronicle's naming rules, return to [Projection Declaration Language](index.md).
