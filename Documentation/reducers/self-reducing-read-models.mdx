---
title: Self-reducing read models
description: Declare static state transitions on a read model without a separate reducer class.
---

Keep a read model's transitions beside its state when a separate reducer adds no useful separation. A self reducer uses the same reducer pipeline, storage, filtering and replay machinery as a classic reducer; only the invocation adapter differs.

## Declare the transitions

Declare public static `Reduce` methods on the concrete, non-generic read model. You need neither a marker attribute nor a parameterless constructor. Each method receives an event and the nullable current model, and returns the next state.

<ChronicleClientTabs snippet="reducers/self-reducing-read-models/basic" />

The first matching event for an event source receives `null` current state. Returning a new model creates or updates it; returning `current` ignores the event; returning `null` leaves it absent or deletes an existing instance. A later event can recreate it.

| Part | Supported shape |
| --- | --- |
| Declaration | Public static, non-generic method named `Reduce` |
| Parameters | `(event, current)` or `(event, current, EventContext)` |
| Event | Non-`object` class or interface dispatch target |
| Current | Exactly the containing model type, nullable or nullable-oblivious |
| Result | The model or `Task` of the model, including nullable results |

No by-ref, optional, `params`, extra service or reordered arguments are accepted. Plain `Task`, `ValueTask`, and `Task<object>` are not state results. Async results are awaited before the next event. An explicitly non-nullable current parameter is a near miss: Chronicle can pass null even if the compiler annotation promises otherwise.

## Discovery and upgrades

The complete static shape is the discovery signal, not the method name alone. An existing non-`IReducer` class with that shape becomes a self reducer after upgrading. Methods with other shapes remain helpers. A static near miss whose current or result refers to its model logs a discovery warning and is skipped; explicit registration rejects it with `InvalidSelfReducerSignature`.

Once a type has a valid self-reduction method, invalid sibling `Reduce` declarations and malformed replay hooks fail validation. A valid handler matching no event in the owning client's registry creates no observer subscription. Unmarked events can participate when explicitly registered; assembly membership alone is not event membership.

Types implementing `IReducer` or `IReducerFor<T>` always remain classic, even with a self-shaped static helper. Their instance activation, dispatch and plain-`Task` behavior are unchanged.

### Arc query endpoints

Arc's default query discovery is separate from Chronicle's reducer discovery: a static `Reduce` returning its read model would otherwise be picked up as a query. With an Arc version that ships `RequireQueryAttribute`, mark the combined model `[ReadModel(RequireQueryAttribute = true)]` and mark only intended query methods `[Query]`. This prevents `Reduce` from becoming a query endpoint without reserving names globally. Older Arc versions do not gain this endpoint suppression from Chronicle.

See Arc's [model-bound read models and queries](https://github.com/Cratis/Arc/blob/main/Documentation/backend/csharp/queries/model-bound/index.md) for its query discovery contract.

## Configuration and explicit registration

Place reducer configuration on the model itself: `[Reducer]` for identity, sequence and activity; shared sequence, event-store, tag and route attributes for their existing purposes.

<ChronicleClientTabs snippet="reducers/self-reducing-read-models/configuration" />

Use the existing generic or `Type` `RegisterReducer` APIs at the composition root. There is no separate self-reducer registration API. Equal explicit and discovered declarations coalesce; incompatible identities fail rather than silently replacing each other. Store snapshots and reconnect lifetime follow [explicit artifact registration](../clients/dotnet/explicit-artifacts).

<ChronicleClientTabs snippet="reducers/self-reducing-read-models/explicit-registration" />

In the same client catalog, a self model cannot also be maintained by another reducer, a fluent projection, or genuine model-bound projection mappings: `AmbiguousReadModelBuilder` rejects that ownership conflict. Shared configuration such as `[Passive]`, `[Reducer]`, sequence selection and filters does not by itself establish projection ownership. Remove the old builder when moving a model to self reduction.

## Handler selection

Dispatch considers only concrete events registered in the owning client:

1. An exact event parameter wins.
2. Otherwise the nearest base-class handler wins over interface handlers.
3. Otherwise the uniquely most-derived matching interface wins.

Equally specific handlers throw `AmbiguousSelfReducerMethod`. This includes two handlers for the same parameter with and without context. Declaration order and method names do not break ties. Separate clients can select different event sets without sharing registry-dependent dispatch or fingerprints.

The implementation fingerprint includes selected handlers and replay hooks, including inherited bodies and async state machines, together with the registry's selected identities and generations. Existing kernel replay policy determines how changed implementations rebuild state.

## Optional replay hooks

Each hook is independently optional. Global hooks have service arguments only; partition hooks require `Partition` first. All must be public static non-generic methods returning exactly `Task`.

<ChronicleClientTabs snippet="reducers/self-reducing-read-models/replay-hooks" />

Trailing class/interface services are resolved from the delivered notification's async DI scope. Events, `EventContext`, the model and extra partition arguments are not hook services. Missing registrations fail loudly. Chronicle awaits the hook and scope disposal before later notifications; an absent hook creates no scope and no model is activated.

Hooks follow the existing notification stream. A full replay sends global begin/end notifications; do not assume it also sends partition notifications. Failure does not guarantee a later end notification. Replay and delivery are not exactly-once operations.

## Reads, filters and preserved limits

- `[Passive]` on the model selects on-demand by-id reduction. `[Reducer(isActive: false)]` only disables active observation; it does not turn materialized reads into passive reads. See [passive reducers](passive-reducers).
- Passive reads and reducer scenarios apply the same tag/source/stream-category matching as active delivery: OR within tags, AND across categories. `Tag`/`Tags` label observers; they do not filter events. There is no stream-id subscription filter.
- A bounded `GetInstances(eventCount)` takes a prefix of event-type-selected events **before** metadata filtering, not the first N accepted events. All-rejected or empty histories produce absent state.
- Materialized snapshots are current stored state. `GetSnapshotsById` returns no reducer history today; it is not an arbitrary-date reducer query.
- `Watch` supports reducers, but `GetWatcherFor` remains projection-only. A failed fold can still notify watchers; a notification is not proof of successful persistence ([#4817](https://github.com/Cratis/Chronicle/issues/4817)).
- Inbox forwarding currently drops append tags for both classic and self reducers. Source/stream routes are preserved; do not rely on tags crossing stores until [#4823](https://github.com/Cratis/Chronicle/issues/4823) is delivered.
- Generation delivery, revisions and PII use the shared reducer engine. Passive/history queries retain classic query-generation behavior; they do not acquire pinned observer-delivery guarantees.
- Reducer decision reads remain unsupported. Container naming follows the existing naming policy; there is no reducer `ContainerName` override.

Use [ReadModelScenario](../testing/read-models/scenario) for transitions and metadata-filter examples. It substitutes compliance and does not prove encryption, erasure, storage, replay or transport behavior; those require real-kernel specifications.

## Diagnostics

`CHR0058` warns about near-miss signatures, `CHR0059` errors on malformed hooks, and `CHR0060` errors on definite declaration ties. `CHR0061` errors on definite ownership conflicts within one type and warns on possible peer ownership. Registry/plugin/separate-client membership remains runtime authority rather than a compilation error. Model state is not classic mutable reducer-service state.
