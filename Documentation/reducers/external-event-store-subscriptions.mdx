<span id="subscribe-reducers-to-external-event-stores"></span>

Cratis Chronicle's .NET client can subscribe a reducer to another event store by forwarding its handled event types from the source outbox to a local inbox. Use event-store metadata when Chronicle should select the inbox and create the subscription for you.

For a subscription you configure yourself, use [explicit event-store subscriptions](../subscriptions/explicit-subscriptions.mdx).

[Self-reducing read models](self-reducing-read-models) use the same inbox routing. Chronicle derives their subscription event types from the static transitions selected by the owning registry, not from query methods or unrelated helpers.

## Automatic Inbox Routing

Declare the source with `[EventStore("...")]` on event types or their assembly. When the handled events identify a single external source and the reducer has no explicit event sequence, Chronicle selects that source's inbox. Events belonging to the current store continue to use the local event log.

## Observer-Level EventStore for Missing Event Metadata

When event contracts cannot carry `[EventStore]` metadata, apply `[EventStore]` directly on the reducer.

Chronicle selects that source's inbox and creates or reuses the outbox-to-inbox subscription. For a self-reducing read model, put `[EventStore]` on the model instead.

## Implicit Combined Event Type Filtering

Chronicle creates one implicit subscription per source event store, combining the handled event types of participating reducers and reactors. External-store projection subscriptions also contribute their event types to this combined filter.

Adding a reducer that handles another event type widens the subscription's event-type filter; it does not create a separate subscription for that reducer. The source forwards the combined set to the target inbox, and each reducer still receives only the event types and metadata matches it observes.

## Explicit Event Sequence Is Not Allowed with Observer EventStore

When a reducer has `[EventStore("...")]`, do not combine it with:

- `[EventSequence("...")]`
- `[EventLog]`
- `[Reducer(eventSequence: "...")]`

The .NET client rejects this combination with `EventStoreCannotBeCombinedWithExplicitEventSequence`; analyzer rule `CHR0014` reports it at compile time. Remove the explicit sequence to use automatic inbox routing, or remove the reducer's `[EventStore]` to select a sequence yourself.

## Forwarded metadata

<span id="forwarded-metadata-limitation"></span>

Inbox forwarding preserves append tags, event source type, and stream-route metadata. Both separate reducers and self-reducing read models can use [metadata filters](filtering) to select forwarded events.

Events forwarded by earlier releases that dropped tags remain untagged; upgrading does not backfill them. Check the stored inbox metadata when an older event does not match a tag filter.
