A separate Cratis Chronicle reducer keeps state-transition code outside the read model. That code is
the fold: it combines an event with current state to produce the next state. Use the .NET
`IReducerFor<T>` form when the fold needs injected services, instance behavior during replay, or
separation from a shared model contract. This guide builds an order summary from creation and item
changes, then reads it by order ID.

If the transitions can live on the model, start with a
[self-reducing model](self-reducing-read-models.mdx) instead. If you have not yet chosen between
mappings and reducer code, [compare the read-model styles](../projections/choosing-a-read-model-style.mdx)
first.

## Prerequisites

Use an application already configured with Chronicle and its event types. Append all events for one
order with the same event source ID, and use that ID when reading its summary. An `OrderId` property
in an event does not replace the event source ID used to route the fold.

The item handlers return `null` if creation has not produced a summary yet. Once state exists, each

The event context also supplies the event source ID and sequence number. TypeScript handlers can
take it as a third argument after the event and current state.

### .NET dispatch and diagnostics

In .NET, the event must be the first parameter and the nullable current read model the second. An
optional third parameter must be `EventContext`. Return the model or `Task<TReadModel>`, including a
nullable result. Returning null deletes or leaves the instance absent. Classic plain `Task` is also
accepted, but yields null state; a mutation-only `Task` handler does not retain current state. A method
taking the current model first and `object` second is not dispatched.

The .NET analyzers report unsupported signatures as **CHR0006** and event parameters without `[EventType]` as **CHR0007**, including `object` event parameters. If none of a reducer's methods can be dispatched, the client skips its kernel registration and logs a warning naming the reducer and explaining why its public reducer-like methods were skipped. The application still starts; correct the signatures so the reducer can observe events.

### 3. Using the Reducer Attribute (Optional)

You can customize the reducer using the `[Reducer]` attribute:

<ChronicleClientTabs snippet="reducers/getting-started/reducer-attribute" />

| .NET parameter | Effect |
| --- | --- |
| `id` | Identifies the reducer; defaults to its fully qualified type name. |
| `eventSequence` | Selects the sequence to observe. Without it, Chronicle infers the event log or the inbox for one foreign source store from the handled event types. More than one source store is rejected. |
| `isActive` | Enables active observation; defaults to `true`. |

The example explicitly selects `order-events`. Omit that selection when the normal inferred sequence
is what you need; see [Event sequences](event-sequence.mdx) before choosing a different one.

Use the client tab's configuration shape. TypeScript expresses identity and sequence through the
`reducer()` decorator; Kotlin and Java use `@Reducer`.

## Event Processing

Chronicle keeps each order's state separate and applies its events in sequence order. The first call
in a delivered batch starts from the stored state, which can be `null`. Each later call receives the
previous call's result, not a fresh read from storage. The batch's final successful result is what
gets persisted.

Return `current` unchanged to ignore an event. Return `null` only when the state should remain absent
or an existing instance should be removed.

## Best Practices

Compute state from recorded facts. An injected clock or live rate service can return different
values during replay; put time and rates in events when they determine the result. Keep external
side effects out of the fold because retries and replay can invoke it again.

Create new state rather than mutating `current`, and copy nested collections before changing them.
Test events that arrive without prior state as well as the expected order history. This catches
missing null handling before an observer encounters it.
