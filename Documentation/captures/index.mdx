Cratis Chronicle captures turn changes in external data into events in your event store. Use a capture to detect changes in API data or translate another event store's public events into your own private events, without writing that detection or translation loop yourself.

:::caution[Execution limits]
The engine runs API-polling captures and events captures with root-level `append` rules. It does not run webhook or message-topic sources, `map` transformations, `nested`/`children` scopes, or expression-based `when` conditions. Validation reports these constructs as unsupported and prevents the capture from starting.

Field assignments support item properties and literals. Events captures also support `$context.<property>` and `$eventSourceId`; API captures do not. See the [CDL execution limits](capture-declaration-language/index.md#execution-scope-and-limitations) before choosing constructs for any authoring approach.
:::

## HTTP source destinations

API polling uses the Kernel's independent `ExternalServices` destination policy. Development builds
warn by default; other builds block local destinations unless their host is explicitly approved.
Redirects and proxies are disabled, and both relative and absolute capture routes are checked with
the capture's event-store context. Webhook approvals do not apply. See
[HTTP capture destination policy](../external-services/index.md#http-capture-destination-policy)
for modes, private-network approvals, metadata protection, configuration, and upgrade guidance.

## Overview

For API data, a capture polls a configured service and compares each observation with the previous one. An identity key, such as an invoice ID, tells Chronicle which items to compare. Append rules select the event to emit when an item is added, removed, or changed, and field assignments build its payload. This is change data capture (CDC): the events describe changes in the source data rather than commands sent to your application.

An events capture reads public events delivered through an inbox, the event sequence that receives events from another event store. It merges their payloads into state for each key, then applies append rules to produce local private events. Use this when your event store needs its own interpretation of another store's public contract.

Capture Declaration Language (CDL) is the language-neutral text format parsed by the kernel. If you prefer definitions alongside application code, .NET offers a declarative API with fluent C# builders and a model-bound API with attributes. The Elixir capture DSL compiles module definitions to CDL. Choose the authoring page under [Topics](#topics) for the approach you want to use.
