Replay notifications tell a reactor or reducer when Cratis Chronicle begins and ends a [replay](replay). Use them to coordinate replay-specific work, such as changing how a reactor writes to an external index. They are lifecycle calls, not a mechanism for preventing duplicate side effects.

In C#, implement `ICanBeNotifiedWhenReplay` on the reactor or reducer class to receive `BeginReplay()` and `EndReplay()`. The interface lives in the `Cratis.Chronicle.Observation` namespace. Store any state needed across those calls outside the reactor or reducer instance.

## Notifications are separate from events

A notification does not go through the event handlers, so a `[Replay]` handler does not receive it. Replay events are delivered between the lifecycle calls. To change which handler processes those events, use [Replay](replay); to skip a handler during replay, use [OnceOnly](once-only).

## Each notification gets a new instance

The .NET client creates a reactor or reducer in a new dependency injection scope for each notification and disposes it afterwards. `BeginReplay()` and `EndReplay()` run on different instances, separate from the instances handling events. An instance field set in `BeginReplay()` therefore cannot tell an event handler that replay is active.

For state shared within one application process, use a singleton service such as the one in the reactor example. A scoped or transient service is created anew for each notification. A singleton does not share state across application processes or preserve it after a restart; use storage outside the process if your coordination needs either.

## Replaying a single partition

Replaying one partition, for example with the [`observers replay-partition`](/cli/chronicle/observers/#replay-partition) command of the Cratis CLI, has its own interface, `ICanBeNotifiedWhenPartitionReplayed`. It receives the partition being replayed:

<ChronicleClientTabs snippet="reactors/replay-notifications/partition" variants="csharp,elixir" />

The two interfaces are independent. Implement the partition interface for single-partition replay, the observer interface for full replay, or both if your coordination must handle either operation.

## What is not notified

In the .NET client, reactors defined fluently with the reactor builder or registered at runtime with a handler delegate do not receive these notifications: they have no reactor class implementing the interface.

For Elixir, use the `on_replay_begin/0`, `on_replay_end/0`, `on_partition_replay_begin/1` and `on_partition_replay_end/1` callbacks. TypeScript exposes `ICanBeNotifiedWhenReplay` and `ICanBeNotifiedWhenPartitionReplayed`. See [Getting started with reactors](getting-started) for the client entry points; the instance-lifetime guidance on this page is specific to .NET.
