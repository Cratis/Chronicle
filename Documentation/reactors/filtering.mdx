# Filter reactors by appended event metadata

Cratis Chronicle reactor filters restrict delivery by event metadata before a handler runs. Use them when one event type serves several workflows but a reactor should handle only a subset, such as priority orders or events from one source type.

Filtering does not remove events from storage or change what other observers receive. It narrows this reactor's subscription within its selected event sequence. Without filters, the reactor receives events of the types it handles.

## Filter attributes

| Attribute | Filters by | Matches when |
|---|---|---|
| `[FilterEventsByTag("...")]` | Appended or static event tag | Any filter tag matches any tag on the appended event |
| `[EventSourceType("...")]` | Event source type set at append time | The event source type matches exactly |
| `[EventStreamType("...")]` | Event stream type set at append time | The event stream type matches exactly |

The table uses .NET attribute names. Set the corresponding metadata when appending the event so the filter has a value to match:

:::note[Client coverage]
Kotlin and Java use `@FilterEventsByTag`, `@EventSourceType`, and `@EventStreamType` on the reactor class. TypeScript provides `@filterEventsByTag`, `@eventSourceType`, and `@eventStreamType` decorators. Elixir's `use Chronicle.Reactors.Reactor` has no options for these metadata filters.
:::

## Filter by tag

To run a handler only for priority orders, append the event with the `priority` tag and configure the reactor to match that tag. In .NET, use `[FilterEventsByTag]`:

The matching `priority` tag allows delivery. An order without that tag does not reach this reactor, even though its event type matches the handler.

## Combine multiple filters

Combine tag, source type, and stream type filters to narrow delivery further. Chronicle requires every configured category to match; the any-tag rule still applies within the tag category:

<ChronicleClientTabs snippet="reactors/filtering/combine-filters" />

Check the append metadata against every configured category when an expected event does not arrive. A matching tag cannot compensate for a different event source type or stream type.

## Tagging the reactor vs filtering events
