---
title: Watch Chronicle Read Model Changes
description: Watch Chronicle read model changes to receive the changed key, current state, and removal flag without replacing a complete collection.
---

Watching a Chronicle read model sends individual changesets containing the changed key, resulting state, and removal flag. Use it to refresh a cache entry or update one item on screen without replacing the complete collection.

`Watch` does not send an initial collection. If the screen needs its current contents followed by replacement snapshots, use [Observing Read Models](observing-read-models.mdx). If application behavior should run for additions, modifications, or removals, a [read model reactor](reacting-to-changes.mdx) can own the dispatch and subscription.

Watch support and subscription syntax differ by client. Choose your client tab in the examples; the field names below describe the .NET changeset.

## What a change contains

A .NET `ReadModelChangeset<TReadModel>` contains:

| Field | Meaning |
| --- | --- |
| `Namespace` | The Chronicle namespace where the change happened |
| `ModelKey` | The read model key that changed |
| `ReadModel` | The resulting state, which can be absent for a removal |
| `Removed` | Whether the instance was removed |
| `ChangeType` | The reported change type; reducer watches report non-removals as `Modified` |
| `ChangeContext` | Causing event context for a projection watch; reducer watches supply only the model key |

The changeset does not contain the previous state. Check `Removed` and whether `ReadModel` is present before reading properties. To compare two observed states, keep the last value for each key. If a reaction depends on the original business event, use an [event reactor](../reactors/) instead.

The filter does not reduce the server's notifications for that read model type. A predicate on `ReadModel` can also exclude removals, because a removed instance may have no state. If you maintain a local list, handle removals by key separately or use a [collection observation](observing-read-models.mdx).

## When to use this

Watch when the consumer can own a long-running subscription and needs to act on one changed key at a time. It suits cache invalidation or an interface that already has state and can apply incoming changes.

For a value needed only once, [read the instance on demand](getting-single-instance). To inspect how a projection reached a value, [get its snapshots](getting-snapshots). Neither task needs a permanent subscription.

A watch follows derived state; it is not a substitute for event-reactor processing. Use [event reactors](../reactors/) when the behavior depends on the domain event and its ordered processing rather than a read model notification.
