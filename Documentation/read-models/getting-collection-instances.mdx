title: Read a collection of Cratis Chronicle read models
description: Read all instances of a Cratis Chronicle read model for a small report or diagnostic task, with guidance on filtering, replay limits, and paging.
---

Read a whole collection in Cratis Chronicle when a small report or diagnostic task needs every instance of a read model. Without an event-count limit, the read returns stored instances for a materialized model and computes passive models from events.

The caller receives the entire result, so use [materialized paging](materialized-pagination) for list views or large data sets. A small number of instances can still have a long event history; allow for replay work as well as the size of the returned collection.

## Read all instances

<ChronicleClientTabs snippet="read-models/getting-collection-instances/basic" />

For a materialized model, the kernel pages through the sink, the storage destination updated by its observer, and releases compliance-protected values before returning the stored instances. The result reflects observer progress; reading all instances does not wait for the observer to catch up.

For a passive model, the read processes the events that feed it and returns the computed instances. The work grows with the relevant event history. This is a collection read, not a guard for a later append; use [decision-consistent reads](decision-reads.mdx) when a command depends on state remaining unchanged.

A [per-stream read model](per-stream.mdx) cannot be read as a whole collection. Read one source and stream instance explicitly instead.

## Filter in memory

Filtering after the read does not reduce the events processed or the instances returned to the client. Use language-native filtering when the complete collection is small enough to load first.

<ChronicleClientTabs snippet="read-models/getting-collection-instances/filtering" />

For large result sets, page the materialized read model or use a product-specific query model instead of reading everything and filtering afterward.

## Limit the replay

Pass an event-count cap to process a limited number of matching events from the beginning of the history. This requests replay even for a materialized model; it does not limit the number of stored instances returned.

<ChronicleClientTabs snippet="read-models/getting-collection-instances/event-count" />

A cap bounds replay work, but later events may change or remove the instances it returns. Use it to inspect a prefix of history for diagnostics or back-testing, not when the reader expects current state. For historical state of one key, continue with [Getting Snapshots](getting-snapshots).

## When to use this

Read the whole collection when:

- The read model population is small.
- You are running an administrative or diagnostic task.
- You are validating data derived from the event log.

Prefer paging or a database-native read when:

- The page is user-facing and called frequently.
- You need server-side filtering, sorting, or paging.
- The read model has many instances.
