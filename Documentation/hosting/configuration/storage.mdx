# Storage

Configure the storage backend for Chronicle Server.

## Storage types

| Type | Description |
| --- | --- |
| `MongoDB` | MongoDB (default) |
| `PostgreSql` | PostgreSQL |
| `MsSql` | Microsoft SQL Server |
| `Sqlite` | SQLite (embedded, file-based) |
| `InMemory` | In-memory (ephemeral, non-durable) |

> [!NOTE]
> Only `MongoDB` storage supports a multi-node cluster. `PostgreSql`, `MsSql` and `Sqlite` register no cluster
> membership provider, so run a single node on them. See [Clustering](clustering.md).

## MongoDB

```json
{
  "storage": {
    "type": "MongoDB",
    "connectionDetails": "mongodb://localhost:27017"
  }
}
```

### Database-name prefix

Set `storage.databaseNamePrefix` to isolate Chronicle's databases on a shared MongoDB server:

```json
{
  "storage": {
    "type": "MongoDB",
    "connectionDetails": "mongodb://localhost:27017",
    "databaseNamePrefix": "staging_"
  }
}
```

The prefix is prepended verbatim to every database name, including the global `chronicle+main` database, event stores, namespaces, read models, Orleans reminders, cluster membership, and jobs. For example, `chronicle+main` becomes `staging_chronicle+main`, and `Orders+es+Default` becomes `staging_Orders+es+Default`. All nodes in a cluster must use the same prefix.

The default is an empty string: existing database names remain unchanged. Changing the prefix selects different databases; it does not rename or migrate existing data. The complete name, including the prefix, must satisfy MongoDB's naming rules and 63-byte limit. Choose a short prefix without spaces or MongoDB's forbidden characters.

For environment-variable configuration, use `Cratis__Chronicle__Storage__DatabaseNamePrefix`. The development-only kernel reset preserves the global cluster database and, when a prefix is set, drops only other databases starting with that exact, case-sensitive prefix. Use a unique prefix when sharing a server; a prefix is a naming boundary, not a substitute for database permissions.

## PostgreSQL

```json
{
  "storage": {
    "type": "PostgreSql",
    "connectionDetails": "Host=localhost;Port=5432;Database=chronicle;Username=chronicle;Password=secret"
  }
}
```

## Microsoft SQL Server

```json
{
  "storage": {
    "type": "MsSql",
    "connectionDetails": "Server=localhost;Database=chronicle;User Id=chronicle;Password=secret;TrustServerCertificate=True"
  }
}
```

## SQLite

```json
{
  "storage": {
    "type": "Sqlite",
    "connectionDetails": "Data Source=/data/chronicle.db"
  }
}
```

## In-memory

The in-memory backend keeps every event sequence, observer, read-model sink, and system record in process memory. There is no connection string, and `connectionDetails` is ignored.

```json
{
  "storage": {
    "type": "InMemory"
  }
}
```

> [!CAUTION]
> The in-memory backend is **not durable** — all data is lost when the process exits, and it is scoped to a single process (it does not share state across a cluster). Use it for tests, samples, and ephemeral environments, not for production data.

When you host Chronicle programmatically, select the in-memory backend with the `WithInMemory()` builder extension instead of configuration:

<ChronicleClientTabs snippet="hosting/configuration/storage/in-memory" />

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| type | string | Yes | Storage type: `MongoDB`, `PostgreSql`, `MsSql`, `Sqlite`, or `InMemory` |
| connectionDetails | string | Conditional | Connection string for the chosen storage backend. Required for all backends except `InMemory`, which ignores it |
| databaseNamePrefix | string | No | Prefix prepended to every MongoDB database name. Defaults to empty; ignored by other storage backends |
