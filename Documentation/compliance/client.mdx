Cratis Chronicle uses your client declarations to identify personally identifiable information (PII) and encrypt it when events are appended. Declare personal data on an event property when the classification belongs to that field, or on a reusable concept type when the value is personal wherever it appears.

:::note[Client coverage]
C#, Kotlin/Java and TypeScript support property and concept declarations; Elixir supports field declarations and `Chronicle.Concept`. The examples below use each client's syntax. The `IServiceCollection` registration at the end of this page applies only to .NET.

See [Marking data as PII](./pii) for the declaration paths supported by each client. Before adding a PII concept to an existing event, review the stored history: changing the classification does not encrypt earlier values.
:::

## Option 1 — Annotate your event types

Annotate individual properties on your event records when a value is personal in the context of that event. In .NET, the annotation is `[PII]`:

<ChronicleClientTabs snippet="compliance/client/property-annotation" />

On a new append, `FirstName` and `LastName` are encrypted. `Department` and `StartDate` remain plaintext. If you are adding annotations to an existing model, read [Adding PII to an existing event type](pii#adding-pii-to-an-existing-event-type) before relying on erasure.

### When to use this approach

Use property-level annotation when:

- The property type is a primitive (`string`, `int`) and you do not need a dedicated concept type.
- The value is PII in this event but is conceptually not a PII concept elsewhere.
- You are classifying selected fields in an existing model and have reviewed the earlier plaintext values.

### Limitation

You must repeat the annotation whenever another event carries the same personal value. Without a marker on the property or its type, the kernel has no PII classification to apply and stores the value as plaintext.

## Option 2 — Annotate your ConceptAs types

A concept is a domain type that wraps a value, such as `PersonName` wrapping a string. Put the PII declaration on that type so event properties retain the classification when they reuse it. In .NET, mark the `ConceptAs<T>` type with `[PII]`:

> [!TIP]
> For the full `ConceptAs<T>` declaration pattern and placement rules, see [Declaring PII on a concept](pii-with-concepts) and <xref:Fundamentals.Concepts>.

### When to use this approach

Use concept-level annotation when:

- The value represents a domain concept that is inherently personal (a person's name, email address, phone number, national ID).
- The same kind of value appears in multiple events and you want consistent protection without repeating the attribute.
- You are building a new model and want the personal-data classification to travel with the type.

Prefer this approach for values that are personal by nature. It still depends on retaining the concept type in the generated schema; replacing it with a plain string loses that classification.

## Combining both approaches

The two approaches complement each other. Use concept types for inherently personal domain values, and use property-level annotation for one-off cases where creating a concept type is not warranted.

## EventSourceId cannot be marked PII

Keep event source identifiers non-sensitive and readable because Chronicle uses them for key lookup. In .NET, applying `[PII]` to a type that inherits from `EventSourceId` or `EventSourceId<T>` throws `PIINotSupportedOnEventSourceId`. Other clients enforce this restriction differently; follow it regardless of the client.

<ChronicleClientTabs snippet="compliance/client/event-source-id-restriction" />

If the identifier itself is sensitive, use a non-sensitive surrogate key as the event source identifier (a randomly generated `Guid` works well) and store the sensitive value in a `[PII]`-marked event property.

## Registering compliance services

In a .NET ASP.NET Core application, `AddCompliance()` registers the providers that read PII annotations:

<ChronicleClientTabs snippet="compliance/client/registering-compliance" />

This registers `PIIMetadataProvider` for property and type metadata. `AddCratisChronicle()` already includes the call. The providers supply declarations during schema generation; the kernel applies encryption using that schema.

Next, mark the personal properties in any projection destination. An event annotation does not automatically protect every read-model property that receives its value; [Read models and PII](read-models) explains that separate storage and release path. These declarations do not authorize access or establish GDPR compliance by themselves.
