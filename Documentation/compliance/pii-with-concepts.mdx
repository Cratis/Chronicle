Declare personally identifiable information (PII) on a concept type when the value is personal wherever you use it. A concept wraps a value in a domain type, such as `PersonName` wrapping a string. Cratis Chronicle carries the type's classification into event and read-model schemas, so each property using that type needs no separate PII annotation.

:::note[Client coverage]
C#, Kotlin/Java and TypeScript support declarations on their `ConceptAs` types; Elixir supports them through `Chronicle.Concept`. Select your client in the examples for its declaration syntax.

This page focuses on resolving PII from a property's concept type. See [Marking data as PII](./pii) for the other declaration paths and their client-specific limits.
:::

> [!TIP]
> For background on the `ConceptAs<T>` pattern, see <xref:Fundamentals.Concepts>.

## Why concept-level declaration is preferred

A property-level declaration must be repeated on every event or read model that carries the value. If a new property uses a plain string with no PII marker, the schema does not tell Chronicle to encrypt it.

Putting the declaration on `PersonName` lets the schema generator find it wherever that type is used. The benefit depends on keeping the concept type: copying the value into an unmarked string property does not carry the classification with it. A projection destination needs its own PII metadata, either from the concept or a property annotation.

## Optional constructor parameters

In the .NET client, a concept parameter that defaults to null retains its underlying type and
`[PII]` metadata in the precise schema. Supplying a value therefore encrypts it just as it does
for a required parameter. Read models always use this shape; event registration uses it when the
kernel advertises precise event type schema support.

If an older schema omitted the classification, adding it does not encrypt earlier values. See
[Adding PII to an existing event type](pii#adding-pii-to-an-existing-event-type) before assuming
that erasure protects that history.

## Placement

Concept types belong in the feature folder they are primarily associated with, or at the feature root if they are shared across slices. Do not create a separate `Concepts/` folder — keep concepts co-located with the code that uses them.

```text
Features/
├── Employees/
│   ├── PersonName.cs          ← shared across Registration and Updates slices
│   ├── Registration/
│   │   ├── Registration.cs    ← uses PersonName
│   └── Updates/
│       ├── Updates.cs         ← also uses PersonName — encryption is automatic
```

## Combining with details

Use the optional `details` parameter on `[PII]` to explain why the value is classified as personal. The text is stored in the schema as documentation; it does not enforce a retention period, establish a legal basis or authorize access.

## What cannot be marked PII

### EventSourceId types

In .NET, marking a type that inherits from `EventSourceId` or `EventSourceId<T>` with `[PII]` throws `PIINotSupportedOnEventSourceId`. Chronicle needs a readable event source identifier to look up the key. Keep the identifier non-sensitive in every client, even where validation differs.
