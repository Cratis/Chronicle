---
title: "CHR0075: Batch method has a signature Chronicle cannot call"
description: "CHR0075 reports a Cratis Chronicle reactor or reducer batch method whose parameters or result Chronicle cannot supply or read."
---

## Rule description

Chronicle calls a batch method with arguments it knows how to supply, and reads its result in a fixed way:

- A reactor batch method takes `(EventBatch batch, BatchContext context)`.
- A reducer batch method takes `(EventBatch events, TReadModel? current, BatchContext context)` and returns `TReadModel?` or `Task<TReadModel?>`. Returning `null` removes the read model.
- On a self-reducing read model the batch method is `public static` and named `Reduce`.
- After those, a batch method can take a `CancellationToken` and services from the service provider. `BatchContext` is optional.

CHR0075 reports a batch method that takes an `EventContext` (each event in the batch carries its own), a second `EventBatch`, a primitive, value type or string, a `ref`, `out`, `in`, `params` or optional parameter, or is generic. For a reducer it also reports a missing or mistyped current read model, a result that is not the read model, and a batch method on a self-reducing read model that is not static or not named `Reduce`.

Chronicle refuses to register an observer whose batch method has any of these problems, with one exception: the client discovers a self-reducing read model's batch method by the name `Reduce`, so a batch method with another name is not found at all. A read model whose only reduce method it is never runs and nothing fails, which is why the analyzer reports it.

## Severity

Error

## How to fix

Change the signature to the shape the message names.
