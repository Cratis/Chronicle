# CHR0044: [Join] of a [PII] value cannot prove compliance subject equality

## Rule Description

A join carries `[PII]` while its source shape appears to use the read model's own subject, but source analysis cannot prove that every joined event was persisted under that subject.

The warning covers a model-bound `[Join]` whose `on` is omitted or names the apparent subject, a fluent root join whose `On` names that subject, and a valid child `Children(...).IdentifiedBy(...).Join<TEvent>()`. Child joins may omit the callback completely and AutoMap the event onto the child.

An event source id selects a stream. It is also the default compliance subject, but append metadata can persist a different explicit subject and historical events retain that value. An event type's `[Subject]` declaration therefore describes a possible source of the runtime value; it does not prove equality for every stored event.

Keep personal values on an owner-scoped read model or resolve them at the query edge. If application-level evidence guarantees equality, suppress the warning at the join and record that invariant where append behavior is controlled.

## Severity

Warning

`CHR0038` remains an error for the established case where an explicit join property differs from the read model's apparent subject. `CHR0044` is separate so the broader, conservative runtime-subject analysis is a non-breaking analyzer addition.

## Suppressing

Suppress with `#pragma warning disable CHR0044` around the declaration, or set `dotnet_diagnostic.CHR0044.severity = none` in `.editorconfig`.
