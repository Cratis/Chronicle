---
title: Close a scoped stream in Cratis Chronicle
description: Use ClosedStreamScope in Cratis Chronicle to close one event source's stream, and check its expected tail before rejecting further appends.
---

Use `ClosedStreamScope` in Cratis Chronicle to close one event source's stream without closing other sources that share its stream type and id. Pass the scope to `CompleteStream`, with an expected tail when the close depends on the history you have read.

The two-argument `CompleteStream(streamType, streamId)` closes that pair across every event source. The examples below use the .NET scope API to narrow the close to one report or extend it to every stream of one entity. If you need another combination, start with the [scope dimensions and matching rules](index.mdx#choose-a-scope).

## Close one event source's stream

Set the event source id together with the stream type and stream id. This closes the April stream for one report; it leaves other reports using `monthly-report` / `2026-04` open:

The scope has three dimensions set, so an append is refused only when it carries all three values.

## Close every stream of an event source

To stop all future appends for an entity, use `ClosedStreamScope.ForEventSource`. It sets only the event source id, so the closure covers every stream of that source, including its default stream. This also works when the entity's events use no explicit stream id:

<ChronicleClientTabs snippet="closing-streams/scoped-closing/close-source" />

`ClosedStreamScope.ForStream` is the matching helper for the stream type and stream id pair, and it is what the two-argument overload uses.

## Close only if nothing landed

An approval followed by a manual close takes two calls. If another event arrives between them, the approval may no longer describe the history you intended to close. Pass the approval's sequence number as `expectedTailSequenceNumber` so the kernel checks for that change before closing.

The kernel compares the expected number with the scope's tail, meaning the sequence number of its last event. It performs that check and the close in the same step. A changed tail returns `ExpectedTailMismatch` and writes no closure:

<ChronicleClientTabs snippet="closing-streams/scoped-closing/close-expected-tail" />

A scope with no matching events has the tail `EventSequenceNumber.Unavailable`. Events appended elsewhere in the sequence do not change this scope's tail and do not cause a mismatch.

In the example, an accepted approval supplies the expected tail. A failed append returns before attempting the close. The result treats `AlreadyCompleted` as success because a manual closure already covers the scope. That check runs before the expected-tail check, so retrying a successful close does not fail with a tail mismatch.

:::tip[Prefer a closing event when a domain fact ends the scope]
If approval itself should end the scope, declare it as a [closing event](closing-events.mdx). The kernel then writes the closure after the event without allowing another append between them. The [crash-recovery limit](index.mdx#guarantees-and-limits) still applies.
:::

## Handle the errors

Check the result before treating the scope as closed. An expected-tail mismatch needs a new decision based on the current history, not a retry with the same number:

<ChronicleClientTabs snippet="closing-streams/scoped-closing/handle-errors" />

| Error | What to do |
|---|---|
| `AlreadyCompleted` | A manual closure covers the scope. Usually a success from your point of view |
| `DefaultStreamCannotBeCompleted` | Add an event source id or another specific dimension |
| `EmptyScope` | The scope has no dimension set. This is a bug in the caller |
| `ExpectedTailMismatch` | Read the stream again and decide whether to close |

Event-driven closures alone do not produce `AlreadyCompleted`. The call succeeds and writes a manual closure as well, which a `ReopenedBy` event can no longer undo.

After a successful close, use [Inspecting and repairing](inspecting-and-repairing.mdx) to check the persisted scope or investigate an unexpected rejection. Manual closures have no normal client reopen call; undoing a mistaken close requires the operator repair path.

To take the scope from an event source definition rather than construct it from strings, follow [Close a stream of a definition](../event-sources/closing.mdx). For the relationship between a closed scope and decisions based on its history, see [Dynamic Consistency Boundary in Chronicle](../dynamic-consistency-boundary/chronicle.md).
