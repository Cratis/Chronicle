---
title: Declare closing events in Cratis Chronicle
description: Declare a Cratis Chronicle event that closes a stream scope after append, choose the scope it closes, and name the events allowed to reopen it.
---

A closing event in Cratis Chronicle is a domain fact that tells the kernel to close a stream scope after storing the event. Use one when the fact itself ends a reporting period or another part of an entity's history, so the log records why further appends are refused.

For example, `ReportDelivered` can close a report's stream. Unlike a separate `CompleteStream` call, the declaration leaves no opportunity for another append between the closing fact and its closure. The event and closure are separate durable writes, though; [Guarantees and limits](index.mdx#guarantees-and-limits) explains recovery after a kernel stop.

## Choose the scope

By default, the closure matches the event source id, stream type and stream id supplied with the append. All three must match for a later append to be blocked. To close a different [scope](index.mdx#choose-a-scope), select the dimensions with the attribute's `Dimensions` value or the builder's `PerEventSourceId()`, `PerEventSourceType()`, `PerEventStreamType()` and `PerEventStreamId()` methods.

To take the stream id from the event's payload instead of the append, use `EventStreamIdFrom` (attribute) or `EventStreamIdFrom(@event => @event.Period)` (builder). That implies the stream id dimension. This is useful when the closing fact names the period it closes while it is appended somewhere else:

<ChronicleClientTabs snippet="closing-streams/closing-events/event-stream-id-from" />

A scope resolving to only default-stream values is refused for both closing and reopening events; it cannot close the default stream for every event source.

A property-sourced value must be present. If it is missing, null or empty, the kernel refuses the append with a violation naming the property rather than closing something broader. Make the property non-nullable. The analyzer [CHR0012](../code-analysis/CHR0012.mdx) warns on nullable event properties.

## What happens on append

Once the closing event is accepted, later appends inside its scope fail with `StreamClosed`. The closure does not affect appends outside that scope:

<ChronicleClientTabs snippet="closing-streams/closing-events/append-after-close" />

`AppendMany` evaluates events in order. Events after a closing event are refused if they fall inside its scope, and the batch result identifies them. If the batch closes, reopens and then appends to that scope, the closure no longer blocks the final event.

A closing event cannot be appended into a scope that is already closed. The closed-stream check applies to it like to any other event.

## Reopen with an event

Name the event types that lift the closure with `ReopenedBy` (attribute) or `ReopenedBy<T>()` (builder). This keeps reopening in the domain history; choose an event whose payload expresses the reason when that matters to the business.

A `ReopenedBy` event removes only its own constraint's closure for the exact scope it resolves to. It is exempt from that constraint's closure, so it can be appended inside the scope it reopens. Manual closures and other constraints' closures still apply. If an operator also closed the scope with `CompleteStream`, that manual closure blocks the reopening event.

When the declaration uses `EventStreamIdFrom`, every reopening event type must have that property too. The .NET client throws `PropertyDoesNotExistOnEventType` during constraint discovery if it is missing.

## Ownership and names

Each closure belongs to its constraint. The constraint name defaults to the event type name. Set `Name` on the attribute or pass `name` to the builder to choose another. Two declarations that share a name merge into one constraint, with their closing and reopening event types combined. They must use the same dimensions and stream id property, otherwise the client throws `ConflictingClosesStreamDeclarations`. The empty name is reserved for manual closures.

Set `EventSequences` on the attribute to restrict a declaration to specific event sequences. Empty means all.

## Not retroactive

Registering or changing a declaration applies it to future appends; it does not close scopes based on events already stored. To rebuild closures from history, run a reindex that names the closing constraint. Read the [rebuild and redaction limits](index.mdx#guarantees-and-limits) before relying on it for recovery.

Appends can continue during a rebuild. The job hands its progress back to the event sequence, which restores later claims and closures overwritten by the rebuild. Closing-constraint commits write only differences instead of first deleting every closure owned by the constraint. Rebuilding unique constraints still has a window between clearing a scope's values and restoring its claims.

## Streams of an event source definition

When the stream belongs to an [event source definition](../event-sources/index.mdx), append the closing event through the definition to that stream. [Close a stream of a definition](../event-sources/closing.mdx) shows that path. For decisions based on the closed scope, see how closure relates to a [Dynamic Consistency Boundary](../dynamic-consistency-boundary/chronicle.md).
