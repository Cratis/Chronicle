# Appending with Tags

Chronicle lets you associate tags with appended events. Tags are stored as event metadata and can be used for categorization and filtering. There are two kinds: plain tags, which are simple strings, and named tags, which pair a name with a value.

The tags you add don't take part in concurrency control. A [concurrency scope](./concurrency.mdx) narrows by the built-in metadata tags below and by event type.

## Built-in metadata tags

Chronicle maintains built-in metadata tags for event identity and stream routing:

- `EventSourceType`
- `EventSourceId`
- `EventStreamType`
- `EventStreamId`

You can add custom tags in addition to these built-in tags. For the full list and behavior, see [Event Metadata Tags](../concepts/event-metadata-tags.md).

## Custom tags

Custom tags are simple strings that you provide when appending. They are merged with any static tags defined on the event type.

## Named tags

A named tag pairs a name with an exact value, for example `checkout-session` = `c-81f2`. Use one when you want to find events by a runtime identifier later. [Tagging](../concepts/tagging.mdx#named-tags) explains the matching rules and how to query by named tag.

Named tags are stored separately from plain tags. You can pass both on the same append, and neither affects the other.

### AppendMany with named tags

Each event in a batch can carry its own named tags, and the append call can add named tags that apply to every event. Chronicle merges the two for each event:

- An exact duplicate of a name and value pair is kept once.
- The same name with a different value stays as a separate tag.

<ChronicleClientTabs snippet="events/appending-with-tags/append-many-named-tags" />

Transactional appends through a unit of work accept named tags the same way.

:::caution[Check the server and storage before you rely on named tags]
An older Chronicle server rejects named-tag appends instead of dropping the tags; the .NET client surfaces an `RpcException` with status code `Unimplemented`. The SQL storage provider doesn't support named tags yet, so these appends fail with `NamedTagsNotSupported` there. MongoDB and in-memory storage support them.
:::

Named tags are plaintext and are not encrypted by the compliance features. Don't put secrets or personal data in them.
