# Getting state

The tail sequence number in Cratis Chronicle identifies the latest appended event matching a read's filters. Use it to capture a boundary for a history read or to compare with an observer's progress. It says what has been appended, not what a projection, reactor, or reducer has finished processing.

In .NET, `IEventSequence.GetTailSequenceNumber` returns that position. A read with no matching events returns `EventSequenceNumber.Unavailable`; do not save that sentinel as an event locator. A captured tail does not freeze the sequence or prevent duplicate processing when you resume.

For point-in-time read models, follow [Getting snapshots](../read-models/getting-snapshots.mdx) and check the snapshot requirements rather than treating a tail value as a snapshot. To read current query results instead, use [Getting a Collection of Instances](../read-models/getting-collection-instances).

This .NET call calculates the tail for the event types handled by the observer; it does not read the observer's progress. Compare that boundary with the observer's recorded position and check for failures or quarantined partitions before concluding that processing is complete. See [Observers](../concepts/observers.mdx) for progress and recovery.

TypeScript provides `getTailSequenceNumberForObserver`, and Elixir provides `get_tail_sequence_number_for_observer/2`. These helpers calculate a relevant event tail, not a completion guarantee.
