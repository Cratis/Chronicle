# Copying events

Copying appends new events to a target event source that carry the same content as the events of a source event source. Use it when a stream has to be seeded from another one — splitting an aggregate, creating a variant of an entity, or restoring an identity under a new key.

The source events are left untouched. Each copy is a new event with a new sequence number, so observers see the copies like any other append.

## How it works

Copying is a durable job. The call returns the identifier of the job straight away, and the job reads the matching source events in order and appends them to the target in batches. You can follow it on the Jobs page of the Workbench, or through the jobs service.

- Each copy is appended with a key derived from the job and the source event, so a job that is resumed after a restart never appends a copy twice.
- A copy keeps the event type, its generation, the tags, the stream, and the original occurred time.
- Personal data is released from the source and protected again for the target. An event whose subject was the source event source gets the target as its subject, while an explicit subject is kept.
- If the target refuses an append — for example because a unique constraint is violated — the job fails and reports it. Copies appended before that point stay in the target.
