# Filter reducers and reactors by event source type

Configure an event source type filter on a reducer or reactor when it should only handle events appended with that source type. In C#, use `[EventSourceType]`; the tabs show each client's syntax.

## How the match works

Chronicle compares the observer's filter to the event source type supplied when appending the event (`eventSourceType:` in C#). If the values do not match, the reducer or reactor is skipped.

## Filter a reactor by event source type

<ChronicleClientTabs snippet="events/filtering/by-event-source-type/reactor" />

The reactor is only invoked for events appended with `eventSourceType: "customer"`.

## Filter a reducer by event source type

<ChronicleClientTabs snippet="events/filtering/by-event-source-type/reducer" />

If you append the same event with `eventSourceType: "supplier"`, this reducer does not receive it.

## Combine with other filters

You can combine the source type filter with tag or stream type filters. When you do, Chronicle requires all configured filter categories to match.

## Filter by a declared event source

In .NET, to get the event source type from an [event source definition](../../event-sources/defining.mdx) instead of a string, use `[FromEventSource<TSource>("Stream")]`. See [Filter observers by event source and stream](../../event-sources/filtering.mdx). The event source type is one of the values a concurrency scope can narrow to, which makes it part of a [Dynamic Consistency Boundary](../../dynamic-consistency-boundary/chronicle.md) guard. A filter on an observer is not.
