title: "Cratis Chronicle: query and watch read models"
description: Read one instance, a collection, or a live page in Cratis Chronicle. Choose stored state for lists or passive reads when the latest events must be included.
---

Cratis Chronicle lets you retrieve a read model by key, load a collection, or subscribe to live changes. Use materialized state, stored by a projection or reducer, for lists that can tolerate a delay after an append. Use a passive read model when the read must compute state from the event log rather than wait for that stored state to catch up.

The C# examples use `IReadModels` through `IEventStore.ReadModels`. Start with a registered read model and the projection or reducer that builds it. If you still need to choose that shape, read [Designing read models](../concepts/designing-read-models) first.

:::note[Client coverage]
The client tabs show each client's API, not identical capabilities. Kotlin's suspending API includes collection reads, materialized paging and live pages; the Java blocking wrapper exposes single-instance lookup. Elixir provides `Chronicle.all/1`, materialized paging through `Chronicle.ReadModels.query/2`, and change messages through `Chronicle.ReadModels.watch/2`. TypeScript streams individual changes through `readModels.watch()`, alongside its single, bulk and paged reads.
:::

## Get one instance

`GetInstanceById` returns the instance for one key. By default it reads materialized state from the sink, the storage used by the projection or reducer. That read is eventually consistent: the model may not yet include a recent append. Marking the read model `[Passive]` makes the lookup compute state from the key's events on demand instead:

<ChronicleClientTabs snippet="scenarios/real-time-query/get-one" />

`ReadModelKey` converts implicitly from `string`, `Guid`, and `EventSourceId`, so you can pass the id you already have.

## Get all instances

`GetInstances` returns every instance in one call. It reads the sink for a materialized model and computes from the event log for a passive one. Keep this for small collections: filtering the returned set with LINQ still loads the whole set first.

## Page through materialized state

For a catalog or grid, use `Materialized` to fetch only the page you need from stored state. This avoids replaying event history for the read, but does not remove the delay between appending an event and the projection updating its sink:

## Watch every change

Use `Watch<T>()` when you need individual changes rather than a replacement page. It returns an `IObservable<ReadModelChangeset<T>>`; each changeset identifies the key, carries the new state, and reports whether the instance was removed:

<ChronicleClientTabs snippet="scenarios/real-time-query/watch-changes" />

Dispose the subscription when the consumer stops watching. For a projection-backed model, use `GetWatcherFor<Book>()` when you need to await the watcher's `Subscribed` signal before producing events.

:::note
During a rolling kernel upgrade, change watches may miss changes from kernel nodes, or silos, still on the previous version. Re-establish watches once all nodes run the same version.
:::

## Observe a live page

Use `Materialized.ObserveInstances` for a table that should replace its current page as stored data changes. It pushes page snapshots, so the consumer does not need to poll:

<ChronicleClientTabs snippet="scenarios/real-time-query/observe-page" />

After a command appends `BookBorrowed`, the projection updates the materialized `Book` and the subscription can receive a new page. The gap between append and push is the [eventual consistency](../read-models/consistency.md) window; do not treat subscribing as a guarantee that a just-appended event is already visible.

To serve a live page to a frontend, Cratis Arc can expose observable queries with generated TypeScript proxies. [Displaying data](/components/displaying-data/) shows how to connect those queries to a table.

## Pick by consistency

| You need | Use | Consistency |
|---|---|---|
| One instance | `GetInstanceById<T>(key)` | Eventual by default; strong for `[Passive]` models |
| A small collection | `GetInstances<T>()` | Eventual by default; strong for `[Passive]` models |
| A page for a list or grid | `Materialized.GetInstances<T>(skip, take)` | Eventual |
| To react to every change of a type | `Watch<T>()` | Pushed as changes apply |
| A live-updating page | `Materialized.ObserveInstances<T>(skip, take)` | Eventual, pushed |
