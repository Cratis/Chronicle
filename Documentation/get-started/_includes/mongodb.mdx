## MongoDB

When you read Chronicle's read models with the MongoDB driver, the driver has to expect the documents Chronicle
writes. Three things matter:

- Chronicle adds metadata fields of its own, such as `__subject`, so the driver must ignore elements your type does
  not declare.
- Identifiers such as a `Guid` key are stored as standard UUIDs.
- Element names match your property names exactly as declared, and each collection is named after its read model,
  pluralized. Chronicle only writes camel-case names if you opt into its
  [camel case naming policy](/chronicle/configuration/camel-casing/); match the driver to whichever policy you chose,
  or queries match nothing without reporting an error.

:::note
These conventions match how Chronicle names and shapes the stored document, but the driver still builds the instance
itself — Chronicle's own read behavior does not travel with it. The one that bites is a child collection with no
children, which is stored as an absent field: read through Chronicle and a non-nullable property comes back empty,
read it with the driver and it comes back as whatever the driver does with a missing field. See
[Empty child collections](/chronicle/read-models/empty-child-collections/).

It doesn't travel the other way either: these conventions apply to the reads you make with the driver, never to a
read model Chronicle hands back or injects into a command. See
[What a MongoDB convention pack reaches](/chronicle/sinks/#what-a-mongodb-convention-pack-reaches).
:::
